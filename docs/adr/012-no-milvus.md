# ADR-012: 不引入 Milvus,pgvector 为向量存储终局选型

日期: 2026-10-19

状态: 已接受(架构裁决已委托;roadmap 第四梯队「向量规模化(Milvus)立项
排序其后,开工先写 ADR」之 ADR,结论为否决立项)

## 背景

roadmap 第四梯队 2026-10-18 净缺口登记将「向量规模化(Milvus)」列为
ai-platform 对齐调研后的第二立项项,约定开工先写 ADR(技术栈锁定流程)。
owner 同期定调:本项目为求职学习与能力展示项目,「等触发信号」式挂账
等不到信号,裁决要么落地要么正式收口——本 ADR 即该收口。

现状:向量存储全量在 PostgreSQL + pgvector——rag 域表说明/查询历史/
user_memory/document_chunks 四处 `vector(1536)` 列 + HNSW 索引(含
部分索引形态:休眠记忆不背索引死重、父块不进索引),与全文检索(tsvector)
同库同事务;召回链路(三路召回 + RRF 融合 + 检索精排)全部 SQL 形态,
零额外网络跳。

## 决策

**不引入 Milvus(或任一独立向量数据库);pgvector 为本向量存储的终局
选型,规模化翻转条件见下节(登记为工程事实,非挂账等待)。**

量级测算(裁决依据):

| 维度       | 现态与可预见量级                                                       | pgvector 承载   | Milvus 增量价值                              |
| ---------- | ---------------------------------------------------------------------- | --------------- | -------------------------------------------- |
| 向量规模   | 表说明千级、文档块万~十万级、用户记忆千级,响应至百万级,现量级余量 >10x | HNSW 毫秒级     | 十亿级/分布式分片才开始有意义                |
| 检索一致性 | 召回与业务数据同库,写入与索引同事务                                    | 强项(单库 ACID) | 双写一致性反成负担                           |
| 部署面     | 单 pg 容器(localenv 单源收敛)                                          | 零增量          | +1 有状态服务(独立存储/etcd 元数据/运维备份) |
| 召回链路   | 三路召回 SQL 化,RRF 在库内融合                                         | 零网络跳        | 多一跳 gRPC,故障面+延迟面双增                |
| 过滤语义   | 元数据过滤(租户/可见性/休眠)与向量检索同库 WHERE                       | 原生            | 跨系统过滤需冗余同步                         |

Milvus 的工程价值域(超大规模、多副本水平扩展、标量+向量混合检索引擎)
在孔明全部场景之外;引入即纯运维负债,且召回链路多一跳网络违背「数据问答
低延迟」王牌体验。作为学习素材,pgvector 深度用法(部分 HNSW/半精度/
混合检索融合)已覆盖向量检索工程主线,独立向量库的运维面不构成增量学习
价值。

**翻转条件(何种事实出现时本 ADR 才重开)**:单表向量行数持续超千万且
HNSW 召回 P95 退化至影响问答体验;或出现多副本水平扩展的真实部署需求。
二者均属产品规模事实,个人项目阶段按现有量级测算不可达。

## 与既有决策的关系

- ADR-001(技术栈否决清单):本决策与「不引入非必要中间件」同哲学,
  Milvus 入该清单同类否决口径;
- ADR-004/Alembic 基线:`vector` 扩展与 HNSW 索引为既有 schema 事实,
  本决策零迁移零回归;
- ADR-010(五大方向):问答智能体方向的检索深化(rerank/分词/融合)
  全部在 pgvector 形态内完成,向量库更换不是任何方向的依赖;
- roadmap 第四梯队:「向量规模化(Milvus)」项以本 ADR 收口,从净缺口
  序列移除;「MCP 运行时熔断」解除排序阻塞,顺位即开工。

## 后果

- 召回链路维持单库 SQL 形态,零新增服务与凭证面;
- roadmap 净缺口序列收敛为 MCP 运行时熔断一项(当期即落地);
- 未来若翻转条件出现,重开 ADR 时迁移面 = 现四处向量列的导出重建
  (embedding 由模型侧可再生,迁移成本低,不构成提前引入的理由)。
