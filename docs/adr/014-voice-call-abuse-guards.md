# ADR-014: 语音通话滥用防护——服务端预算闸与上游收口边界

日期: 2026-11-25

状态: 已接受(add-voice-call-guards 落地)

## 背景

ADR-013 把声音直连给浏览器,后端只做牵线与文字事件控制。复盘发现一个结构性
缺口:**后端无法终止已经建立的模型会话,通话收口依赖浏览器配合。** 改过的
客户端可以忽略结束通知继续与模型对话;文字通道断开后后端释放准入,浏览器仍可
保留媒体连接。于是「一人一通 + 并发上限 + 单次时长」的封顶只对诚实客户端成立。

百炼官方文档(2026-11-25)给出硬边界:

- 单次会话最长 **120 分钟**,到点由服务端主动关闭;600 秒是上下文音频保留
  时长,不是会话持续时间。
- `qwen3.8-omni-flash-realtime` 建连 RPM 60、TPM 2,000,000;限流页在 WebSocket
  一节说明未单独限制同时连接总数,WebRTC 未单列并发上限。
- 客户端事件里没有 `session.close`;WebRTC 结束会话只能由客户端停止媒体并
  关闭 PeerConnection,没有服务端关闭接口。
- 临时 API Key 默认 60 秒、可设 1–1800 秒,继承生成它的 API Key 全部权限,
  不能提前删除。

## 决策

### 1. 不改变媒体直连,不引入中转

当前没有 WS-only 供应商、受限网络、电话/录音或多供应商故障切换的承诺需求。
中转不会自动带来厂商可移植性,还要新增媒体服务、TURN、转码、CPU、安全面与
运维,并劣化时延。带宽不是决策因素:2 路并发下裸 PCM 约 1.3–1.7 Mbps,
100 路 Opus 约 7–10 Mbps;真正成本在 CPU 与运维。

重开条件(任一成立才立项):①Gemini 等 WS-only 供应商成为承诺需求,且浏览器
WS + ephemeral token 的体验不可接受;②受限网络、SIP/电话或服务端录音成为
承诺需求;③并发或供应商限制成为瓶颈;④多供应商故障切换成为产品需求。触发后
优先托管或成熟开源媒体服务(LiveKit/Pipecat/Pion),独立部署;先做 10/50/100
路压测再定并发上限;不自研媒体泵,不在 api 进程里搬运 PCM。

### 2. 服务端建连频次与 24 小时预算

- 同一用户固定 60 秒窗口的建联次数上限(`KM_VOICE_ESTABLISH_RATE_PER_MINUTE`,
  默认 6,0=关闭)。
- 用户与部署各一条滚动 24 小时成功建联预算
  (`KM_VOICE_DAILY_CALLS_PER_USER` 默认 20、`KM_VOICE_DAILY_CALLS_PER_DEPLOYMENT`
  默认 100,0=关闭)。
- 计数在 Redis,原子占用、建立失败逆序释放;释放到 0 时删除计数键,24 小时
  窗口从首个成功建联起算。频次超限 429 `VOICE_RATE_LIMITED`,用户预算 429
  `VOICE_DAILY_LIMIT`,部署预算 429 `VOICE_BUSY`。
- 预算闸对 Redis 故障 fail-open;准入仍 fail-closed,同源故障下准入会先拒绝,
  不会因预算 fail-open 产生无闸暴露。
- 日预算拒绝落 `chat.voice.call_rejected` 审计;频次拒绝只记日志,避免刷审计。

预算按成功建联次数近似,不按 token 精确计费;上游 120 分钟硬上限决定单次最坏
暴露,两者相乘即部署侧的成本上限。多账号轮换不在本决策范围。

### 3. 审计归属与口径

- 建交通话走 `kongming.tenant.resolve_tenant` 白名单校验;未声明取默认租户,
  无法确定返回 `403 TENANT_FORBIDDEN`。审计记录校验后的租户。
- 轮数、打断次数、音频用量来自浏览器转发事件,只作参考,不作计费依据;
  计费以百炼控制台账单为准,建议配置费用/用量告警。

### 4. 票据与帧上限

- 通道票据优先走 `Sec-WebSocket-Protocol`,访问日志只记路径;query 保留一版
  兼容,前端铺开后删除。
- 应用层单帧上限 64KB,超限 `close(1009)` 并正常收口;api 镜像 uvicorn
  `--ws-max-size 262144` 作为内存层硬闸。

## 备选与否决

| 方案                          | 否决理由                                                                 |
| ----------------------------- | ------------------------------------------------------------------------ |
| 媒体改回后端转发 / 部署 SFU   | 与 ADR-013 的时延与容量取舍冲突;无承诺需求;另立 ADR 后再做               |
| 下发临时 API Key 让浏览器直连 | 权限继承父 Key 全部能力、TTL 最长 30 分钟、不能提前删除;暴露面更大       |
| 心跳/人机校验/客户端证明      | 恶意客户端可伪造,只增加正常路径复杂度;上游没有服务端关闭接口             |
| 只做频次、不做日预算          | 频次只限制速率,不限制 24 小时累计暴露;僵尸会话可跨窗口累积               |

## 影响

- 正面:恶意客户端的最坏成本由服务端次数上限封顶;审计租户可信;票据不再落
  访问日志;超大帧不再进入状态机。
- 负面:正常用户极端情况下会触顶;预算为近似口径,需要按真实用量校准;多一次
  租户索引查询。
- 多厂商:浏览器传输按厂商能力区分。OpenAI/阿里支持原生 WebRTC;Gemini Live
  官方是 WSS + ephemeral token,没有原生 WebRTC 直连,接入需 provider 专属
  adapter 与浏览器媒体路径,不能只改 base URL/model。
