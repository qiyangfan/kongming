# ADR-013: 语音通话——声音直连、控制回后端、语音模型只当耳嘴

日期: 2026-11-25

状态: 已接受(add-voice-call 变更落地;前置的真取消能力
add-chat-turn-cancel 已归档)

## 背景

孔明的语音能力此前只有批量语音转文字(`/chat/stt` 填草稿):用户不能像打电话
那样连续对话,听不到回答,每一问都要回输入框确认。这是输入输出方式上的真实
缺口,也是通用智能体方向(ADR-010)在交互形态上的空位。

候选形态有三个,分别对照大厂官方做法(OpenAI server-side controls、谷歌
Gemini Live 官方说法、阿里百炼 WebRTC 直连)与小助手(FoxESS ai-chatbot)
的既有实现,并经阿里 `qwen3.8-omni-flash-realtime` 真实通话实测验证(13 次
后端连接 + 1 次浏览器直连,约 0.02 元,2026-11-24)。

## 决策

**声音直连、控制回后端、语音模型只当耳嘴。**

- **声音直连**:浏览器与语音模型服务经 WebRTC 直传声音,音频媒体不经过孔明
  服务器(每路通话约 0.85 Mbps 未压缩声音,Python 控制面当音频泵会在时延、
  抖动、回声三面全劣化;OpenAI、谷歌、阿里官方都不建议把声音流过应用服务器)。
  实测浏览器直连 0.04 秒连上,无中转。
- **控制回后端**:浏览器与后端之间加一条只传文字事件的通道(WebSocket,一次性
  票据鉴权),浏览器把模型会话的事件原样转给后端;发给模型的内容只限后端指示
  转发的。对话的每一步决策、每一次记录都留在后端。
- **语音模型只当耳嘴**:包括问候与闲聊在内,每一句语音提问都走与打字提问
  完全相同的问答链路(权限、租户、配额、SQL 防火墙、落库、评分),语音模型
  只负责「听写」与「念出」。不让它自己作答——那等于绕开 SQL 防火墙、租户
  数据范围、配额与审计,是孔明的立身之本。

### 备选比较

| 方案                      | 做法                                       | 否决理由                                                                                |
| ------------------------- | ------------------------------------------ | --------------------------------------------------------------------------------------- |
| 后端统一转发媒体          | 声音经孔明转给模型服务                     | 每路 0.85 Mbps 搬运 + 多一跳时延;大厂一致不建议;小服务器扛不住并发媒体流                |
| 浏览器编排(小助手做法)    | 后端只牵线,此后模型与浏览器自由对话        | 后端看不见模型是否擅自作答,无法掐断;记录靠浏览器上报,管控与审计缺位                     |
| **声音直连 + 控制回后端** | 声音直连;文字事件经浏览器搬运,决策全在后端 | **选定**。与 OpenAI server-side controls 同构;阿里无原生旁路通道,浏览器代为搬运文字事件 |

### 信任边界(ADR-002 的延伸)

新增一条「浏览器 ↔ 模型服务」的直连通道。模型服务密钥只存在于 api;浏览器
拿到的只有一次性通道票据与连接应答。后端相信登录用户提交的文字事件,不相信
其转发之外的事——信任模型与「打字提问时相信登录用户提交的文字」同级。准入
(同一用户至多一通)、并发上限、单次时长上限把暴露面封顶;按量计费下白用的
代价极低(实测一通约 0.003 元)。agent 面零改动,零凭证形态不变(ADR-002)。

### 实测确立的两道必配保护

- **掐断擅自回应**:等待问答结果期间模型若自行开始回应,后端见其开始事件立即
  `response.cancel`(实测漏出声音 0.0 秒),该轮问答继续。
- **失效后补交**:模型会话中发生过其他回应时原查询调用编号作废,后端把结果
  作为文字消息补交(实测照念、数字一致),不丢弃。

断句必须用按语义的方式(semantic_vad):普通断句下等待期间一声「嗯」会让
模型编造答案(实测);按语义断句被过滤。等待期模型不出声(调工具的那轮模型
不生成音频,阿里官方文档),补一句预录固定应答。

## 已知限制与重开条件

- 受限网络(禁 UDP)下浏览器直连不可用:建立失败时明确提示「当前网络不支持
  通话」;不部署中转服务器(若未来要求受限网络可用,重开「部署媒体中转」议题)。
- 回声消除依赖浏览器 WebRTC 内置能力;真机回声问题不在服务端解决范围。
- 被取消的回应不报告用量:通话审计如实记录模型报告值,值偏低,不据此计费。
- 多实例部署时在途通话登记在进程内:届时与在途轮登记(share-turn-registry)
  一并外置,当前单节点形态不受影响。
- 语音模型只接阿里一家;多厂商切换不在本决策范围(端口已按本仓惯例留接口反转)。
