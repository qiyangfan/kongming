# ADR-002: 信任边界是不可降级的构造属性

日期: 2026-08-16
状态: 已接受(继承前系统 ADR-002 精神,并强化)

## 决策

> **语言统一,信任边界不统一。** Agent 面与控制面必须是两个操作系统进程
> (两个部署单元),Agent 进程的环境中不存在任何数据库凭证。

## 为什么进程边界不能换成 import-linter

- 进程边界是**构造级保证**:凭证物理上不在 Agent 进程的内存空间与环境变量中。
  即使 prompt 注入将 Agent 打穿到 RCE,泄露面也只有回调用的内部令牌
  (最小权限、可轮换),拿不到业务库凭证。
- import-linter / lint 是 **CI 期约定级保证**:动态 import、`os.environ`、
  `subprocess` 均可绕过。它管住"配合的代码",管不住"被劫持的代码"。
- 本产品路线图含**云代码沙箱**(执行模型生成的代码),"模型产出物不可信"
  是默认威胁模型,进程隔离是命门而非洁癖。

## 实施约束

1. `apps/agent` 的 Docker 镜像与运行环境中,禁止注入任何
   `*DATABASE_URL*`、`*DB_PASSWORD*` 类变量;compose 层面校验。
2. Agent 面调用控制面的唯一通道:`/internal/*` 受控接口,
   认证用内部服务令牌(与用户 JWT 体系分离,可轮换)。
3. 用户请求链路:web → api(用户 JWT)→ agent(内部令牌)→ api(内部令牌 + 请求上下文)。
   Agent 永远不直接面对用户流量、不直接触达数据库。
4. import-linter 仍然保留(防御误用),但定位是**纵深的一层**,不是边界本身。

## 审计口径

任何"把两个进程合成一个以简化部署"的提案,都必须先证明 Agent 面不再执行
任何模型产出物——历史上这不成立。
