# 流式问答事件实施任务

各项完成后运行 `make check` 的对应子项，并在实施记录中写明命令和结果。

## 1. 公开模型与 API 输出

- [ ] 1.1 为六种公开事件定义按 `type` 选择的模型。复用阶段、SQL、总结、工具调用的数据模型以及同步 `ChatQueryOut`，为两种流错误定义必填的 `reason_code`。模型测试覆盖每种合法事件，以及类型与数据错配、额外过程字段、错误枚举、字符串重试次数和空结果。
- [ ] 1.2 收紧 API 消费 Agent 过程帧的入口。在进入阶段记录和发送队列前检查数据，排除诊断 `trace`，用轮次标识和失败类别记录坏消息。先补失败测试，再验证两个 Agent 流入口的合法过程消息可用，畸形 JSON、结构错误、未知事件和内部诊断不会传给网页或污染阶段记录。
- [ ] 1.3 改用有类型的发送队列和统一编码出口。正常、业务失败、无需调用 Agent、显式取消的结果都通过 `to_chat_query_out` 生成 `result.data`。验证问答结果与同步响应使用相同定义，心跳和 `X-Trace-Id`、配额预警及防缓冲响应头可用。
- [ ] 1.4 实现 Agent 结尾选择和 API 输出失败收尾。覆盖无效结果在合法结尾前、重复结尾、读尾异常、缺失结尾、结果转换或编码失败及队列提前结束。对 `persist=true/false` 分别验证结尾数量和保存结果，确认编码失败不会改写已保存的应答或新增失败记录。定向执行 `test_chat_stream.py` 和 `test_chat_turn_cancel.py`。

## 2. 生成接口说明与网页检查函数

- [ ] 2.1 从公开模型生成 200 的 `text/event-stream`、`x-sse-data-schema` 和六个分支。增加接口测试，确认不存在 `application/json` 的 200 响应，六个分支可通过 `type` 区分，并用导出的定义检查代表性的真实响应帧。同步问答响应及流前 HTTP 错误的声明也须通过回归检查。
- [ ] 2.2 将 Ajv 8 的独立校验生成步骤接入 `contracts:gen` 和 `contracts-check`。以导出的事件定义为输入，登记生成文件及其类型声明，按生成文件配置检查范围。验证连续生成内容一致，生成模块无需在浏览器中编译规则，并通过 `make contracts` 和 `pnpm typecheck` 验证产物可用。

## 3. 网页接收与分发

- [ ] 3.1 解析默认 SSE 消息，以生成的函数检查 JSON 后按 `type` 分发。更新 `api.test.ts`，覆盖六种事件、未知类型、错误字段、无效 `result` 和 `error`、合法结尾之后的同分块事件，以及读完仍无合法结尾。新增事件类型后缺少分支须使类型检查失败。
- [ ] 3.2 补齐分帧和读取结束测试，覆盖分块截断的中文、LF、CRLF、CR、同一消息中的注释、多行 `data:`、末尾缺少空行和主动停止读流。保留页面已有的回调和上下文守卫，执行网页定向测试及 `make web-check`。

## 4. 一起验收前端和 API

- [ ] 4.1 运行流式问答、工具调用、文档问答及取消相关的定向测试，覆盖两个 Agent 流入口和 API 输出。比对本轮事件、最终显示和保存的应答，手工走普通问答、ReAct、显式停止、断线后在历史中查看结果四条路径。
- [ ] 4.2 检查网页构建后的校验模块大小，并验证包含较大表格的正常问答可以完整显示。用合并请求相同版本的 `oasdiff` 检查生成契约。若确需接受已批准的事件格式差异，只登记该端点的指定差异，复核其他接口和契约检查仍通过。
