# Tasks: add-sql-semantic-guard

> 语义规则类改动测试先行：先写失败用例，再实现。不依赖历史数据清理、
> 样本信任门控或人工关系播种作为正确性前提；Sakila 只作为实验室夹具。

## 1. 结构化 schema 图

- [ ] 1.1 先写失败测试：图包含表/列/主键/外键/可确定角色；不含连接凭证；
      图缺失或旧响应时保持现有召回行为；桥接表按外键路径补入且不依赖表名
- [ ] 1.2 控制面组装 `schema_graph` 纯增字段：从既有表说明、主键/外键内省和
      关系数据生成；无结构和角色证据时不猜测；缓存按租户+数据源失效
- [ ] 1.3 图驱动桥接表补入：事件表自带员工/门店外键优先；无路径零扩展；
      扩展尾部追加、有界、可观测；主召回和旧响应零回归
- [ ] 1.4 补齐动态数据源 PK/FK 图采集路径：现有 FK introspection 仅覆盖
      default 源；复用语义层契约扩展 active datasource，禁止以人工关系行或
      表名规则兜底；动态源取不到图时角色未知、语义硬规则不启用

## 2. 生成前约束

- [ ] 2.1 Agent 消费结构化图；生成提示仍可用文本 schema_hint，但表/列白名单
      以图为准；旧图缺失时回退现有路径
- [ ] 2.2 先写失败测试：SQL 引用图外表/列时不进入执行，违规项进入定向自愈
      （不产生 execute 调用，不落错误结果）

## 3. 确定性语义校验(测试先行)

- [ ] 3.1 先写表驱动失败测试：金额表计数冒充事件笔数；事件计数关联一对多
      金额表未去重；支付/金额时间冒充事件时间；绕过事件表员工/门店外键走
      商品/库存门店；正确 SQL 与歧义角色不误拒；事件表被金额表外键引用时
      仍判为事件角色，不得因此排除
- [ ] 3.2 实现 AST 语义校验器：输出违规类别、涉及表/表达式/关系路径和定向
      修正指令；只使用图与问句，不调用模型
- [ ] 3.3 接入 validate/selfheal：违规不执行、定向自愈、重试耗尽 fail-closed；
      正确 SQL 与既有防火墙/data_scope 路径零回归
