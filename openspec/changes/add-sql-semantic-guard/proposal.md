# Proposal: add-sql-semantic-guard(结构化 SQL 语义护栏)

## Why

当前生成正确性主要依赖提示词纪律。实测同一条“按月统计门店租赁笔数和总支付金额”，在相同数据源和提示下多次运行会分别产生 `payment` 行数当租赁笔数、用库存所属门店代替租赁门店、以及关联支付后计数被一对多行放大等结果；在提示词中增加规则也不能稳定消除这些漂移。继续靠历史数据清理或再加提示词条文，无法证明下一次生成仍然正确。

需要把正确性从“模型尽量遵守”提升为“代码可判定、可拒绝、可回归”的约束：生成前给模型一份结构化的表/列/外键图，生成后用确定性规则检查 SQL，失败就定向自愈，耗尽预算则拒绝执行而不是把错误 SQL 交给用户。

## What Changes

- 控制面在 RAG 召回响应中增加**结构化 schema 图**：表、列、主键、外键、可确定的表角色；同时按外键图补入问题所需的桥接表（例如事件表到员工再到门店）。不依赖表名启发式，不引入人工关系播种作为正确性前提。
- Agent 以结构化图作为生成和校验的共同事实源；SQL 只能引用图中表/列。
- 在 `validate` 阶段增加**确定性语义校验**，执行前拦截：
  - 图外表/列；
  - 事件笔数在关联一对多金额表后未按事件主键去重；
  - 问事件笔数却从金额表计数、问事件时间却用金额时间（角色可确定时）；
  - 问事件门店/员工归属却绕过事件表自带的员工/门店外键，改走商品/库存维度。
- 校验失败把具体违规项交给 selfheal 定向重生成；重试耗尽返回明确的失败终态，SQL 不执行。
- 增加实验室 gold 用例和纯函数/AST 校验测试；不依赖真实用户数据，不以历史数据纠错作为验收路径。
- 样例/存量数据只作夹具，不作为本变更的生产行为要求。

## Capabilities

### New Capabilities

- `sql-semantic-guard`: SQL 生成前后的结构化 grounding、确定性语义校验、定向自愈与拒绝执行边界。

### Modified Capabilities

- `nl2sql-agent`: 生成与校验改为消费结构化 schema 图；新增确定性语义校验、违规分类、定向自愈和 fail-closed 终态。
- `rag`: 召回响应增加纯增的结构化 schema 图；按外键图补入问题所需桥接表，并对图缺失保持既有降级。

## Impact

- **信任边界(ADR-002)**：Agent 仍零数据库配置与凭证；schema 图只经控制面内部接口下发，图中不含连接信息。Agent 不新增 DB 驱动或直连路径。
- **契约管线(ADR-005)**：`/internal/rag/retrieve` 增加纯增字段并同步生成 OpenAPI/类型；用户侧问答契约不变。需跑 `make contracts` 并提交产物。
- **Schema(ADR-004)**：不新增表、列或迁移；图从既有表说明、主键/外键内省与关系数据组装。角色无法从结构确定时不参与硬拒绝，避免把未知当错误。
- **代码落点**：控制面 RAG 图组装与召回；Agent 的 retrieve/validate/selfheal 状态流；测试与实验室评估夹具。
- **兼容性**：图字段缺失或旧 Agent 未消费时保持既有行为；校验只在新图可用时启用硬规则，旧路径零回归。
- **不涉及**：历史样本信任门控、数据源恢复、语音、UI、真实用户数据采集。

## Non-goals

- **不改变历史样本回写/召回策略**；坏样本清理继续作为测试夹具，不作为本变更的正确性保证。
- **不做表名/租户特判**；不把 Sakila 的 `payment`、`rental` 等名称写进运行时判断。
- **不引入 LLM-as-judge 作为执行前门禁**；本变更的拦截必须是确定性、可单测的规则。
- **不自动改写所有可疑 SQL**：语义违规进入定向自愈，重试耗尽拒绝执行；只对结构上可证明等价且无歧义的局部改写另行设计。
- **不改用户可见问答 API、权限、data_scope、SQL 防火墙或租户边界**。
- **不实现数据源自动切换或通话侧交互**；相关能力已另有提案。
- **不承诺覆盖所有业务语义**；角色无法确定时只执行结构规则，不把猜测包装成正确性。

## Open Questions

- 桥接表补入的预算上限是否复用现有关系扩展上限，还是按图路径长度单独定；在设计中给出默认值并可配置。
- “事件角色/金额角色”的首版判定是纯结构规则还是允许语义层显式覆盖；首版优先结构规则，歧义不硬拒绝。
- 语义护栏失败是否需要在管理面增加独立统计；先复用 stage trace，若运维/质量面需要再立项。
