# Design

## Context

- bot-store 既有:上架/下架为 Bot 行上的状态(无版本概念);护栏审核在
  上架时对**活定义**执行;商店直跑经 025 运行链路消费活定义;零工具闸
  求交口径单源(上架闸与运行闸共用)。
- Bot 定义归属 chat/bot 域;商店行为归属 bot-store 域——版本快照表归
  bot-store 语义域(上架产物),快照消费方跨两域(读取面快照化)。

## Goals / Non-Goals

**Goals:**

- 存量零回归(迁移补 v1 后商店行为逐字段一致)。
- 快照不可变性成为消费侧单点:商店展示与直跑改读快照后,活定义只服务
  草稿态与既有渠道(公开页/api-key)。

**Non-Goals:**

- 既有渠道(公开嵌入/OpenAI 兼容/api-key)的版本化(它们消费活定义是
  既有契约,商店版本化不外溢——channel 语义不同:商店是「他人在货架
  上看到的成品」,自有渠道是「owner 自己的 Bot」)。
- 版本 diff 可视化/草稿对比编辑器(提示「有差异」即可,不做 diff 视图)。
- 多版本并行在架(A/B 上架)——单指针语义,多版本并行无真实需求。
- 评分/收藏/使用量的版本维度(绑定 Bot 不绑版本,历史资产不随版本
  丢失)。

## Decisions

1. **快照 jsonb 而非列展开**:快照是「一段不可变定义」,列展开(五列镜像)
   与定义结构演化耦合;jsonb + 读侧定型(契约 schema)是既有 artifacts/
   audit 的成熟形态。快照字段白名单定型(名称/问候语/建议问题/系统提示/
   工具集),不接受任意 json。
2. **指针而非状态列**:当前上架版本=Bot 行上的版本指针(外键),历史
   版本无独立状态机(在架/下架是 Bot 级开关,版本只有「是否当前」)。
   备选(版本状态机:DRAFT/PUBLISHED/ARCHIVED)引入三态转换矩阵,无
   消费方,否决。
3. **回滚再过护栏**:护栏规则是活的(规则升级后旧内容可能违规);回滚
   免审会形成「绕过现行审核」通道。审核失败拒绝且指针不动(fail-safe)。
4. **幂等上架(内容一致复用)**:防止「反复点上架」制造版本洪水;内容
   一致性判定=快照字段逐项相等(规范化后比较,纯函数可测)。
5. **封顶淘汰保护当前版本**:淘汰只取最旧非当前(当前版本被淘汰=货架
   悬空,禁止);上限部署级可配(缺省 10)。
6. **迁移补 v1**:存量在架 Bot 一律补快照(定义现状)并指向——迁移脚本
   同事务回填;未上架存量 Bot 不补(首次上架时创建 v1)。

## Risks / Trade-offs

- [直跑读快照的回归面] → 商店直跑路径单点改造 + 既有直跑测试全量回归
  (含零工具闸);公开页/api-key 渠道不动(Non-goal 边界)。
- [快照与活定义漂移的 心智负担] → 创建者面差异提示(草稿≠在架)是
  治理补偿;长期看这是版本化的本意(分离是特性不是缺陷)。
- [jsonb 快照的 schema 演化] → 快照读侧定型走契约 schema;新增 Bot
  定义字段时快照白名单同步(测试断言快照键集)。

## Migration Plan

1. 新迁移:版本表 + Bot 指针列 + 存量 v1 回填(同事务);2. 上架链路
   版本化(护栏前移到快照创建后);3. 商店读取/直跑切快照;4. web 差异
   提示与历史视图。回退:revert(版本表留存无害;指针列回退前清空即可)。
