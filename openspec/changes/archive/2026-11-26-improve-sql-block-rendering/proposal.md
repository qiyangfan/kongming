# Proposal: improve-sql-block-rendering(SQL 卡只读优先 + 代码块语法高亮)

## Why

SQL 卡的「可编辑再执行」上线后按真实使用者视角复盘:会写 SQL 的人更愿意把 SQL
复制到自己的客户端改(前端 textarea 没有高亮、补全与校验),业务用户则根本不改
SQL——他们的低频诉求是「只看上个月的」这类条件调整,用一句追问表达即可。编辑入口
放在默认形态上是把低频能力摆到了主位,而这块内容的真实价值是**透明可复核**:SQL
可见、可复制、能据此判断答案可信度。

同时,回答与文档卡里的围栏代码块目前只有等宽与底色,**没有语法高亮**,SQL 作为
数据展示缺少关键字/字符串/注释的区分;两种渲染形态并存也显得不一致。

体积已实测(esbuild min + gzip):

| 方案 | 体积 | 结论 |
| --- | --- | --- |
| refractor/core + sql + 薄 rehype 插件 | **13.2 KB** | 采纳:只注册 sql,预算无感 |
| rehype-highlight(全家言) | 55.4 KB | 备选:零手写但拖入 37 种语言 |
| shiki(core+sql+单主题+JS 引擎) | 65.6 KB | 视觉最好,oniguruma 另需 WASM 资产 |
| rehype-prism-plus | 224 KB | 排除:依赖 refractor 全量 + parse5,超预算 |

体积预算现状:总预算 800 kB brotli,实测约 664 kB,余量约 136 kB;采纳方案预计
+11 kB brotli。

## What Changes

- **SQL 卡默认只读**:折叠块内默认渲染只读代码块(等宽、语法高亮、复制);新增
  次级「编辑」入口,点击后进入可编辑态(复用现有 textarea 与 `POST
  /chat/artifacts/rerun`,再执行/还原语义不变);未进入编辑态不呈现可编辑控件。
- **代码块语法高亮**:MarkdownText 的围栏代码块接入语法高亮,仅注册 SQL 语言;
  无语言标注或未知语言保持等宽原样渲染(不报错)。文档卡与回答正文同源受益,
  SQL 只读态复用同一条渲染管线。
- **设计 token**:新增一组代码高亮颜色变量(关键字/字符串/数字/注释/函数/标点/
  运算符),`index.css` 亮暗双值,组件不出现字面色值。
- **体积复测**:`make web-check` 中 size-limit 复测;预计无需调整预算,实测若
  超出则按新数字登记调整。

## Non-goals

- 不引入 CodeMirror 等可编辑的高亮编辑器,编辑态保持朴素 textarea。
- 不做全语言高亮,仅注册 SQL;其他语言回退等宽原样。
- 不改 rerun 端点契约、审计与安全链路(六层防御照旧)。
- 不做 SQL 保存/分享/收藏等延伸能力。
- 不调整体积总预算(除非实测超预算并登记新数字)。

## 引用

- 纯前端渲染与交互形态变更,不涉及信任边界/认证/schema/契约管线(002/003/004/
  005 不适用)。
- 遵循 `../FRONTEND-CONSTITUTION.md`:基础组件复用、token 单源、暗色一级公民。
