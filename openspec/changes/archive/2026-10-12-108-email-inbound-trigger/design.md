# Design

## Context

- triggers 域现状:cron(调度 tick 轮询)+ webhook(公开入站端点)两类;
  调度器/执行历史(sys_trigger_run)/目标校验/创建者身份执行/防御层复用
  全部就绪;101(失败重试策略,同批提案)将补重试语义。
- webhook secret 已有加密落库与「任何接口不回显」成熟机制,邮件凭证
  直接复用。
- 邮件摘要是外部内容(进目标执行=进 LLM 链路),输入护栏是既有闸。

## Goals / Non-Goals

**Goals:**

- 邮件触发器是「触发器的一种形态」,不是新系统:管理/历史/隔离/执行
  全走既有口径,新增面收敛在配置、轮询器、游标、适配器四点。

**Non-Goals:**

- SMTP 出站(发邮件是通知面,出站通知已有 notify_url 语义)。
- 附件解析/HTML 富正文提取——摘要只取纯文本预览(附件是文档处理域
  的事,越界)。
- 邮件规则过滤(按发件人/主题筛触发)——第一切片全量触发,过滤是
  目标工作流内部的事(条件节点可表达)。
- IMAP IDLE 推送(长连接)——轮询即可,IDLE 是优化不是能力。
- 多文件夹聚合——每触发器绑一个文件夹,多文件夹=多触发器。

## Decisions

1. **imaplib 标准库而非第三方客户端**:IMAP4/IMAP4_SSL + TLS 覆盖目标
   场景,零新依赖(技术栈纪律:能不引就不引);解析用 email 标准库。
2. **UID 游标持久化而非时间窗**:时间窗(上次轮询时刻)在时钟回拨/
   重复投递下不幂等;IMAP UID 是服务端单调标识,`UID SEARCH UID <cursor+1>:*`
   语义精确。游标与触发记录同事务推进——崩溃恢复时「已触发但游标未进」
   的邮件会重触发一次(至少一次语义),目标执行的幂等性由目标域自理
   (与 cron 的 SKIPPED 保护同一哲学:宁可重复不可丢失,重复由 run
   历史可见)。
3. **轮询器挂既有调度 tick**:每 tick 检查到期的邮件触发器(轮询间隔
   独立于 cron 表达式,配置为秒数下限封顶),与前次轮询未完成的记
   SKIPPED(复用并发保护语义)。
4. **摘要字段白名单**:from/subject/date/text_preview 四字段定死——
   邮件头可被构造出注入载荷(主题/显示名),白名单+长度上限+输入护栏
   三层收敛;不透传原始头。
5. **配置形态**:触发器行上加密凭证列 + 明文配置列(host/port/tls/
   folder/interval),游标独立小表(触发器 id+文件夹唯一)——不与
   cron 触发器共用字段(形态不同,列语义不同源更干净)。

## Risks / Trade-offs

- [IMAP 方言差异(服务器 UIDVALIDITY 变更/非常规行为)] → UIDVALIDITY
  变更时游标作废重置(全文件夹重扫会重复触发——记录告警,人工裁决;
  语义宁重复不丢失的一致延续)。
- [轮询风暴(大量邮件触发器)] → 轮询间隔下限封顶 + 每 tick 处理数
  上限(剩余下 tick 续传,游标语义天然支持);单实例调度形态量级无虞。
- [凭证误入日志] → 复用 webhook secret 的脱敏断言测试形态。

## Migration Plan

1. 迁移(触发器配置列 + 游标表,纯增);2. 轮询器 + 适配器(测试以
   内存 IMAP 桩先行);3. web 表单分支。回退 = revert(表留存无害)。
