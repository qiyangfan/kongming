# 设计:块索引上下文注入

## 上下文

- 块正文(content)在分块时已包含本节标题(`# 营业时间\n\n…`),缺的是文档名;
  族谱章节路径不在本次范围(祖先标题不提升为索引文本)。
- 被索引文本有两处消费:入库时子块 embedding(`documents_service` 调内部向量化)
  与 tsv(`to_tsvector(ts_config, content)`);检索问句侧不变。
- 现有同名覆盖上传以 content_hash 幂等跳过,无法用「重上传」触发重建 → 需要独立
  重建路径。

## 决策

1. **索引文本构造集中在入库服务**:`index_text(doc_name, content) = doc_name + "\n" + content`;
   embedding 与 tsv 都改用它,`content` 列保持原文(引用/试跑/回填零变化)。
2. **重建脚本而非双写**:提供维护脚本按块表遍历,重建 embedding 与 tsv;不重切块、
   不改块 id 与父块关系。回滚=回退代码后用同一脚本按原文重建。
3. **不加配置开关**:避免双路径长期并存;灰度靠「先重建评测环境 → A/B → 再生产重建」,
   回滚路径已被脚本覆盖。
4. **判别语料**:生成器增加「正文剥离文档名」变体(v1 形态),固定在评测目录内,
   作为本改动的判别器;既有 15 文档与实验室定版语料做回归。

## 验收口径(运行前登记)

- 判别语料(`retrieval_scale_v1.yaml`,正文剥离店名):旧代码基线**本轮实测**
  融合 Recall@5=0.291、全跳率 0.243(历史 v1 形态 0.818 的问题集店名依赖弱于
  本变体,不作对比基准);改造后融合 Recall@5 提升 ≥5pp,全跳率同步提升。
- 回归:既有语料(15 文档 28 题、实验室定版 74 题)macro Recall@5 劣化 ≥5pp 即失败。
- 行为等价:返回父块正文逐字不变;引用键与试跑结构不变;embedding 维度与模型不变。
- 门槛复核:重建后向量分分布随索引文本变化,用 `calibrate_fulltext_gate.py`
  重测并把新旧分布写入评测记录;若生产聊天路径门槛与新分布明显失配,再单独
  调整配置(不在本改动内改默认值)。
- 单测先行:先写失败测试锁定「embedding 载荷与 tsv 均含文档名、content 不含前缀」。

## 兼容与风险

- 存量库在重建前是「旧索引」:代码上线后到重建完成前,检索仍可用(旧索引语义),
  重建完成后按时新语义;两次状态都通过同名接口,不破坏对外契约。
- 风险:文档名过长或无信息量(如 `说明.md`)时上下文增益有限;重建 embedding 有一次性
  费用,按块数线性。

## 回滚

回退代码提交后,执行同一重建脚本(它按当前代码构造索引文本)即可恢复旧语义;
脚本与评测记录随变更归档。
