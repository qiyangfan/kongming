# 文档块索引上下文注入(文档名 + 块正文)

## Why

实验室规模语料的对照暴露了检索侧的真实缺口:条款正文只写「本店…」、店名仅在文档
标题时,按店名提问的 17/74 题对**所有召回路径**无解,融合 Recall 0.818;把店名写进
正文后回到 1.000。机制:块的被索引文本(embedding 与全文 tsv)只取块正文,不含
文档名;按文档名/文档级实体提问时,召回端没有可用的区分信号。换排序器(精排/BM25/
zhparser)无法弥补——它们重排候选,不改变候选池的构成。

## What Changes

- 入库时构造「被索引文本」= 文档名 + 块正文,用于子块 embedding 与全文 tsv。
- 返回给模型与引用的块正文保持原文不变(不加前缀)。
- 存量文档提供重建脚本:按当前分词配置重算 embedding 与 tsv,不重新切块、不重传文档。
- 评测:A/B 判别语料(正文剥离实体上下文的形态)验证召回提升;既有语料回归不得劣化;
  判定条件运行前登记。

## Capabilities

### New Capabilities

### Modified Capabilities

- `document-rag` 新增「块索引上下文」需求;上传、检索编排、引用与试跑接口行为不变,
  仅被索引文本变化。

## Impact

- 生产检索行为变化:同一问题的父块命中可能变化(预期为改善);一次性重建的 embedding
  调用量=存量子块数,检索耗时不变。
- 无 schema 变更、无对外契约变更;引用仍指向原文块,返回内容不变。
- 评测入口复用 `KM_EVAL_RETRIEVAL_DATASET`;判别语料由现有生成器加「剥离实体上下文」
  变体产出。

## Non-goals

- 不改父/子块切分边界与 overlap;不引入祖先章节路径(块正文已含本节标题)。
- 不改 RRF、精排、分词与实体扩展参数;不新增模型或服务。
- 不改返回正文、引用格式与检索试跑接口结构。
- 不做在线双写或影子索引(一次性重建;回滚=回退代码 + 同脚本重建)。
