# Proposal: 对等圆桌(分析圆桌拓扑)

## Why

091 分工拓扑解决「并行分治」:orchestrator 拆解、worker 各自执行、输出只进聚合——worker 相互不可见,不存在立场交锋与相互质疑。复杂分析任务的另一类质量放大器是**对辩**:多个专家围绕同一问题轮番陈述、质疑、交叉查证,直至收敛或如实保留分歧。外部证据:Anthropic 生产系统明确记录主从编排的同步瓶颈(主智能体无法中途引导、worker 间不能协调);多智能体辩论(MAD)研究证明固定轮次 + 共识判定 + 裁判裁决是可生产的终止策略,而选择性参与可大幅压降 token 成本;黑板模式(共享结构化转写)消灭传话游戏式信息损耗。对等圆桌同时是通用智能体方向(ADR-010「多智能体」)的高展示价值形态。

**方向声明(ADR-010 立项纪律)**:所属「多智能体」方向,宿主方向 = 任务内核(090);落地为 091 协作域的第二种拓扑形态,不新建能力域。

## What Changes

- 协作域新增 **roundtable(圆桌)拓扑形态**:`collab_topology` 支持 `kind: roundtable`——N 个专家参与者(2..部署上限)共享一块**黑板**(orchestrator 管理的追加式结构化转写),结构化轮次对辩,每轮各参与者可发言、查证或弃权。
- 参与者复用 worker 物:一次受限 ReAct 内核实例,可绑定 Bot 人格或使用内置角色章程;工具集恒为「任务授权 ∩ Bot 名单」,空集 fail-closed——**授权不提权口径零变化**(ADR-002 信任边界零改动,工具调用 100% 经既有回调)。
- 显式治理协议(终止三通道):**共识判定**(主席每轮裁决 convergence)/**轮次硬顶**(部署级上限)/**预算耗尽**(与 091 同一 worker 预算池,发言与查证同池计费)——任一触顶诚实收口,未共识时分歧如实保留,SHALL NOT 编造共识。
- 选择性参与降本:轮内可弃权;连续全员弃权即提前收口(回应 MAD 研究的 token 成本结论)。
- 账本与观测:新增轮次转写表(黑板持久化,回放与审计单元);`collab-runs` 查询扩展返回轮次转写;任务事件流新增圆桌生命周期事件;每参与者独立 trace 父子关联、用量按参与者归集(038/077 口径)。
- 091 Non-goal「不做共享黑板」由本变更显式修订:黑板为 opt-in 形态、治理与审计仍单点收口(黑板即审计单元),无自由消息通道。
- 评测:judge 抽检层新增圆桌 rubric(共识质量/分歧诚实/证据接地)。

## Capabilities

### New Capabilities

(无——圆桌是 multi-agent-orchestration 域的既有行为的形态扩展,治理语义同源,不新建能力域。)

### Modified Capabilities

- `multi-agent-orchestration`:协作拓扑要求扩展第二种形态(roundtable:主席 + 参与者 + 黑板);「worker 间无直连」通信收口规则显式区分两种形态——分工拓扑输出只进聚合,圆桌拓扑通信经 orchestrator 管理的黑板(仍无点对点直连);新增圆桌治理协议(轮次/终止/预算)、授权与账本、观测面行为契约。

## Impact

- `apps/agent`:collab_gen 新增圆桌编排核心(轮次循环/黑板管理/共识判定,零 api 句柄)+ collab_wiring 装配(参与者人格注入/工具求交/逐 turn 账本回写);复用既有 ReAct 内核与回调链。
- `apps/api`:task 域扩展——拓扑归一与校验(roundtable 参数 + 部署钳制)、轮次转写表(Alembic 新迁移,ADR-004/VI:UUID v7、VARCHAR+CHECK、已规划列一次建全)、`/internal` 协作回调扩展(turn 上账)、collab-runs 响应扩展;`make contracts` 重生成(ADR-005)。
- `apps/web`:任务详情协作视图扩展圆桌形态(轮次转写时间线,DataView/标准件);契约类型由生成获得。
- 评测:`apps/api/evals/judge` 新增圆桌 rubric 与对象取数扩展。
- 成本面:多轮对辩放大 token——参与者数上限、轮次硬顶、预算同池、选择性参与为四道闸;用量按参与者归集,步级预算闸照常兜底。

## Non-goals

- 不做跨进程分布式协作、不引入消息总线(宪法 Article I 禁项不变;黑板为进程内结构化状态 + DB 持久化)。
- 不做自由点对点寻址与非结构化群聊:发言恒为结构化轮次,无 A→B 私聊通道。
- 不做本地代码执行/沙箱类查证工具;查证动作限于既有只读回调工具。
- 不做实时 SSE 转播(轮次观测走既有轮询 + 转写回放;实时流留待后续变更)。
- 不做嵌套圆桌(深度恒 1,协作嵌套仍为 091 的 opt-in 配置)。
- 不做动态名册:参与者集合在拓扑声明时定死,运行中不自主增减参与者。
- 不做 agent 竞价/谈判等经济机制。
