# Design

## Context

语音通话的文字事件通道把模型会话事件原样交给控制面状态机;问答由模型调用
`ask_kongming` 工具发起,参数由模型生成。人工复测暴露的边界集中在两处:
模型工具参数不完整时原实现直接丢弃事件;网页建立通话的异步锁只在新一轮
建立结束时释放,建立中挂断可能留下锁。见 proposal.md「Why」。

## Goals / Non-Goals

**Goals:**

- 工具参数可恢复的畸形场景不再静默丢问题,能用听写原话回到既有问答链路。
- 单值结果不被播报成「详细名单在屏幕上」,多行结果仍提示页面有数据。
- 建立中挂断后可以立即重拨,旧建立请求不能污染新一轮状态。
- 短句打断更容易触发,同时保留句中停顿容忍。

**Non-Goals:**

- 不更换语音供应商、不引入新的转写服务或媒体中转。
- 不新增工具参数重试协议或公开事件类型。
- 不保证模型一定调用工具;既有未放行回应取消机制仍是最终防线。

## Decisions

### 1. 听写文本作为工具参数兜底

状态机缓存供应商下发的听写 `delta`/`completed` 文本;收到新的说话开始或
成功发起一轮问答后清空。工具参数 JSON 解析失败、不是对象、缺少 `question`
时,用当前听写文本构造同一形态的 `ask_kongming` 调用;没有听写文本则保持
原拒绝并记录日志。

选择这条路径而不是新增「让模型重新生成参数」的重试:重试会增加一次模型
往返且仍可能畸形;听写原话本来就是规格要求的问题文本。代价是依赖供应商
发送听写事件,若实际没有事件则只能保留旧行为,不伪造问题。

### 2. 收紧会话行为说明

把「用户提出查询或问题时交给工具」改为「每一次语音输入都要立即调用
`ask_kongming`,自己绝不直接回答」。这是提示词层面的概率收口,不是安全
边界;模型仍可能不调用工具,此时既有「未放行回应取消」继续兜底。

### 3. 断句阈值与静默下限分离

语义断句阈值取 0.4,静默下限保持 2000ms。阈值降低让「等一下/停」这类
短促语音更容易产生说话开始事件;静默下限保持,避免取数问句中的自然停顿
被提前截断。该取值是调参结果,需要在真实通话中对照误触发率;若环境噪声
导致误打断,回退到 0.5 即可,不需要改协议。

### 4. 结果播报按行数判定

回答文本是否追加「详细数据已显示在屏幕上」由结果行数决定:仅多行结果表或
图表追加;单值计数、单行标量不追加。不能用列是否存在判断,否则「一共多少
位演员」这类单值结果也会被误报成有详细名单。

### 5. 网页拨号锁按请求序号释放

每次建立分配单调递增序号;挂断立即增加序号并清除拨号中标记,使下一次点击
不被旧锁挡住;旧建立请求的 `finally` 只在序号仍等于自己时释放锁,避免迟到
完成清掉新一轮的锁。这样既保证挂断后可重拨,也避免重复拨号。

## Risks / Trade-offs

- [供应商可能不发送听写事件] → 兜底自动退化为原拒绝;记录失败日志,后续
  以真实通话日志确认事件是否存在,必要时另立变更接入转写。
- [阈值 0.4 可能增加噪声误触发] → 保留 2 秒静默下限;真机复测对照,异常时
  回退到 0.5。
- [模型仍可能不调用工具] → 提示词收紧只是降低概率,未放行回应继续由取消
  机制拦截;真实通话日志可定位 `function_call` 缺失。
- [听写缓存可能包含半句] → 新的说话开始和成功发起问答都会清空;兜底只在下
  一次提问参数不可用时使用。

## Migration Plan

无数据库、公开契约或部署配置变化。API 与 Web 可独立发布;回滚时恢复断句
阈值与网页拨号锁实现即可,听写兜底与播报判定可按版本回退。无需迁移。
