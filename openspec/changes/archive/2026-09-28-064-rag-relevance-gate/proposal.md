# 064-rag-relevance-gate 提案:召回相关度闸门(影子先行)

## Why

RAG 三路召回(向量 / `ts_rank` 全文近似 BM25 / `query_history`)经 RRF(`k=60`)融合后**直接取 top-5 进入提示词**。全仓无任何分数闸与质量判断:一条低相关命中与一条高相关命中同样进 prompt。

后果双向:

- **false positive 稀释提示词**,直接压低选表与生成准确率,并白烧 token;
- 若闸门过严,真实知识被挡在门外,退化为"未找到"——这是用户可见的质量倒退。

### 口径修正(本提案 v2,取代 v1 的"融合分绝对闸"设计)

v1 写的是「RRF 融合后新增绝对分数闸 `min_score`」。落地前核验代码,该设计**在当前与目标形态下都不成立**,三重障碍:

1. **分数根本不存在。** `rag/repository.py` 三路召回的 SELECT 列表只有 `schema_name, table_name`:
   向量路的 `embedding <=> :vec` 仅为 ORDER BY 计算后即丢弃,全文路的 `ts_rank` 在 WHERE 与
   ORDER BY 各算一次同样不返回。`rag/models.py:rrf_fuse` 累加分数后只回
   `list[RecallHit]`(无 score 字段)。v1 的闸门没有任何可判的量。
2. **RRF 分不是相关度,是"多路名次共识度"。** 融合值 `Σ 1/(60+rank)` 的取值由**命中路数与名次**
   决定,与"有多相似"无关。在 `RECALL_TOP_K=5` 的现有参数下可直接算出反例:
   **单路第 1 名 = 1/61 ≈ 0.0164,双路并列第 5 名 = 2/65 ≈ 0.0308,是前者的 1.9 倍。**
   即在融合分上拍任何绝对阈值,都会系统性惩罚"只有一路认对、且排在首位"的真命中
   (纯向量召回与纯术语精确命中的典型形态),偏袒"两路都勉强沾边"。
   这是把闸门调反方向的机器。
3. **量纲不可共用。** 向量路的余弦相似度与全文路的 `ts_rank` 是两个尺度;一个 `min_score`
   管不住两路,共用即其中一路形同虚设。

结论:**判据必须落在每一路自己的原生相似度上,RRF 只保留它真正擅长的职责——跨路排序。**

参考实现(上游 FoxESS 问答线,38 变更验证过)独立收敛到同一判断,其取值可直接作为量级校准依据:
它的 RRF 地板是 `0.001`,注释明说刻意比任何合法 RRF 输出低几个数量级(其算式:k=60、rank 0
→ 1/61 ≈ 0.016),因此该地板**只用于过滤空壳命中与元数据丢失,从不承担相关度判定**;
真正的相关度判定落在重排分之上,并在无重排通道时退化为词法核对。本仓不做重排(见 Non-goals),
故判据取"各路原生分 + 跨路印证"双条件。

## What Changes

1. **分数出口前置到 SQL(硬前置)**:三路召回各自 SELECT 回原生分数——向量路
   `1 - (embedding <=> v)`、全文路 `ts_rank(...)`、历史路 `1 - (embedding <=> v)`;
   `RecallHit` 增 `score` 与来源路标识。RRF 融合分一并透出,**只用于排序与观测**。
2. **闸门判在各路原生分数上,且为双条件**:`(过闸命中数 ≥ min_count ∧ 该路 top1 ≥ 该路阈值)`
   **或** `(过闸命中数 ≥ min_count ∧ 前 N 均值 ≥ 次级阈值)`。第二条专治"单条差一点、
   多条互相印证"——这是真实相关的常见形态,单条件判据会稳定误杀它。
3. **阈值按路独立可配**(向量 / 全文两路各自一档),缺省值以影子阶段的分布标定,不凭空拍。
4. **命中数为 0 时不参与判定**:某路零命中即该路不投票,SHALL NOT 把"零命中"当"低相关"。
5. **全路零命中或全部不过闸时**,走既有"知识不足"路径(复用 doc_answer / 短路语义),
   不新增终态、不改响应信封。
6. **影子先行**:shadow 模式只记录"若闸门生效会丢弃多少命中、多少轮次会改变路径",
   不改变任何返回;对拍确认误杀率与收益后切 primary。仓内 053 已建立并验证该灰度范式
   (内置权威 + 引擎并行判定 + 只记录不一致),本变更直接复用,不新建灰度机制。
7. **观测**:各路分数分布、被闸命中数、生效阈值、轮次路径变化进 trace 时间线
   (observability 域既有通道复用,零新采集)。
8. **召回试跑(管理台只读验证面)**:新增 `GET /system/rag/recall-probe`
   (入参=问题+可选数据源;返回=三路命中及各自原生分、融合分、双条件判定结论、
   影子形态下"若生效将丢弃"的记录)。试跑以第 3 条的当前生效阈值为判定基准,
   **零副作用**:SHALL NOT 修改配置、SHALL NOT 落库、SHALL NOT 触发召回缓存失效。
   与 Non-goals「per-datasource 阈值管理台」不冲突——本项是阈值的**验证工具**
   而非阈值管理面:只读、全局、不提供编辑入口。两个高频场景:知识运营上传
   表说明/文档后验证「用户问 X 能否召回它」(此前只能等真实轮次,或月级滞后的
   覆盖报告);影子期标定不等真实流量,3.1 的各路分数分布直方图可由试跑批量产出。

## Non-goals

- **重排模型(cross-encoder / rerank API)——明确不做**。本仓 RAG 语料以术语库、指标定义、
  文档块为主,规模与信号强度尚不证明值得多一次模型调用;引入即新增依赖、延迟与故障面。
  **重估条件(写死)**:document-rag(024)语料规模过千篇,或影子模式显示 primary 切换后
  false positive 仍居高。
- **字符 bigram / 分词重合度话题检查——不做**。上游对该机制留有两次误杀事故的一手注释
  (短问句 bigram 数过少时单点失配即判 0,`min_count` 形同虚设),引入需分词依赖,
  与 `docs/tech-stack.md` 锁栈纪律冲突。本条判据的职责由第 2 点的跨路印证条件承担。
- **在 RRF 融合分上设相关度阈值——禁止**。见 Why 第 2 点算式;后续若确需融合分地板,
  其阈值 MUST 低于任何合法 RRF 输出且只用于过滤空壳,不得复名为"相关度闸"。
- **第四路召回**(如 SPLADE):召回路数已够,当前缺的是收敛而非发散。
- **查询改写增强**:与 046/047/051 正交,不动。
- **per-datasource 阈值管理台**:先用全局可配值;管理台 UI 属过度前置。

## Capabilities

### Modified Capabilities

- rag:新增「召回相关度闸门」Requirement——判据为**各路原生相似度**的双条件判定,
  含分数出口、影子与主力两态可回退、零命中不劣化三项约束;明文禁止以 RRF 融合分充当相关度判据。
- rag:新增「召回试跑」Requirement——管理台只读端点,输入问题返回三路命中、
  原生分、融合分与双条件判定结论;零副作用、与主链路闸门共用同一判定纯函数、
  权限复用 system:rag:manage 不新增权限点。

## Impact

- **落点**:`apps/api/kongming/rag/repository.py`(三路 SELECT 补分数字段)、
  `models.py`(`RecallHit` 增 score/来源路;`rrf_fuse` 透出融合分不改排序职责)、
  `service.py`(闸门纯函数 + 消费点)。
- **shadow 记录**复用 053 的 `sqlfw/guard.py` 观测形态,不新建机制。
- **试跑端点落点**:`apps/api/kongming/rag/router.py`(新只读端点)、
  `service.py`(retrieve→试跑投影,判定与主链路共用同一纯函数);
  apps/web 知识管理页内探针入口(复用既有 rag 管理页,不新开路由)。
- **无 schema 变更**(ADR-004):分数由既有 `embedding` / `tsv` 列表达式算出,不落新列。
- **无 OpenAPI 信封变更**(ADR-005 零触发)——闸门只改变进入提示词的上下文,不改变响应结构。
  但试跑端点为新增管理端点 → `make contracts` 提交产物(ADR-005)。
- **信任边界无涉**(ADR-002):全部改动在 api 面召回路径内,agent 面零感知。
- **依赖**:primary 切换必须以 065 评估门禁对拍为前提;未对拍不得切 primary。
