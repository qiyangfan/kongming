# Design

## Context

- 调度器为 tick 轮询形态(30s 精度,既有);执行历史表
  `sys_trigger_run`(status/error/duration_ms/target_run_ref);
  `sys_trigger` 表无重试相关列。
- 「前次未完成记 SKIPPED」的并发保护与 notify_url 出站推送均为既有语义,
  重试必须与其共存而非绕开。

## Goals / Non-Goals

**Goals:**

- 缺省零回归(不配重试 = 现行为逐字一致)。
- 中间失败可观测(独立 run 行,不抹历史)。
- 与既有 SKIPPED/notify 语义正交组合,不引入第二套判定。

**Non-Goals:**

- 指数退避/抖动(固定退避足够,个人项目无退避风暴面)。
- 手动「立即重试」按钮(执行历史可见后人工重跑走既有启停/等周期)。
- webhook 入站触发的重试(webhook 202 即异步执行,失败重试同策略适用
  与否留待真实需求——本变更只覆盖 cron 触发器语义,cron 与 webhook
  共用 run 表,策略实现天然覆盖两者,spec 不区分来源)。
- 跨进程分布式锁(单实例部署形态,既有调度语义已防堆积)。

## Decisions

1. **调度重排而非执行内联**:内联 sleep 重试占执行协程、拖长「执行中」
   窗口放大 SKIPPED 面;调度重排让重试与普通触发同路派发(同防御层、
   同 SKIPPED 保护),机制零新增——只是调度器多一类「到期任务」。
   实现:`sys_trigger_run` 挂起重试行记 `next_retry_at`,调度 tick 扫描
   到期行派发。备选(内联重试)否决。
2. **独立 run 行 + retry_of_run_id 关联**:中间失败是可靠性证据(运维
   要看「失败 3 次还是 1 次」);覆盖式改写历史是反模式。attempt 序号
   冗余存储换取历史查询免递归。
3. **max_retries 放触发器级**:重试成本(目标执行消耗 LLM/工具配额)由
   触发器 owner 决定,部署级只有退避间隔;0 缺省保证存量零回归。
4. **notify 终态化**:通知消费方关心结果不关心过程,中间态通知是噪音;
   链终态判定(成功或耗尽)后单次发送。
5. **停用/删除取消挂起重试**:停用语义=「不再主动执行」,挂起重试是
   未来时态的执行,必须一并停;重新启用不补做(从下个周期开始),
   避免「停用一小时后启用瞬间轰炸补跑」。

## Risks / Trade-offs

- [重试放大目标执行副作用] → 目标是工作流/Bot 运行,本就按幂等性由
  目标域自理;max_retries 上限 5 封顶 + 确认流写工具照走(重试也要确认,
  无人确认即失败耗尽)。
- [next_retry_at 扫描索引] → 调度 tick 扫描条件(挂起+到期)行数极小,
  加部分索引即可;量级无虞。
- [SKIPPED 与重试交织的语义复杂度] → 规则收敛为一句:SKIPPED 永不重试、
  执行中永不并发;测试覆盖交织场景(重试执行中 cron 到期)。

## Migration Plan

1. 迁移(三列,全带缺省,存量行为零变化);2. 调度器重排逻辑 +
   终态化通知;3. web 表单字段。回退:revert(列留存无害,不 drop)。
