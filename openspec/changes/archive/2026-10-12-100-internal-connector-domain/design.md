# Design

## Context

- 网关域接入范式已两次验证:knowledge(内置收编)与 websearch(部署级,
  094);HTTP 连接器(099,同批提案)将验证租户级动态装配。ticket 域
  回到部署级形态(094 范式),无新表、无动态装配复杂度。
- 写工具确认流、域配额分桶、工具审计、条件注册 fail-closed 语义均为
  既有框架能力,本域纯消费。
- 个人项目无真实工单系统:出站闭环靠 mock 服务撑演示与 e2e——mock 是
  一等交付物,不是测试脚手架的临时凑合。

## Goals / Non-Goals

**Goals:**

- 预置方言域的完整样本:固定工具语义 + 结构化参数 + 标准化卡 + 写确认,
  为后续内部系统(日历等)立接入模板。
- 演示可复现:mock 启动 → 环境变量 → 问答出站 → 审计可查,一条配方走通。

**Non-Goals:**

- 日历/IM 等更多内部系统(各自后续立约,本变更只立工单模板)。
- 租户级自建内部连接器(租户级诉求由 099 HTTP 连接器承担;预置方言
  域保持平台供给)。
- 工单状态机治理、双向同步、webhook 订阅(适配器只透传枚举,不解释)。
- 真实工单系统适配(Jira/ServiceNow 等具体实现的字段映射)——约定
  面向「最小工单 API」,真实系统接入时各自加适配层。

## Decisions

1. **部署级而非租户级**:内部系统凭证属企业部署事实(服务账号),与
   websearch 同谱系;租户级动态面的复杂度已在 099 承担,本域保持简单
   (启动装载、条件注册),两提案对照恰好完整展示网关谱系。
2. **「最小工单 API 约定」而非适配某个真实系统**:`GET /tickets`(query/
   status/limit)、`GET /tickets/{id}`、`POST /tickets` 三端点 + 统一
   JSON 字段命名;mock 按约定实现,真实系统接入=按约定写门面或加适配层。
   约定文档化在 mock 服务文件头与 HANDOFF(单一事实源)。
3. **mock 服务为仓库单文件脚本**(标准库 http.server,内存态,零新依赖):
   e2e 测试与演示共用同一实现——测试过的就是演示的;不进 compose 部署
   形态(演示期手工启动,配方进 HANDOFF)。
4. **权限两点而非一点**:search/get 与 create 分开(读面放宽、写面收紧
   是内部系统的自然授权形态),create 的确认流独立于权限点(有权限
   仍需确认,两层独立)。
5. **枚举原样透传**:状态/优先级不做平台侧中文翻译——翻译表是方言知识,
   放 prompt 层(工具描述里说明枚举语义)而非代码映射,避免语义漂移
   双源。

## Risks / Trade-offs

- [mock 与真实系统形态偏差导致演示失真] → 约定面小(三端点六字段),
  偏差可控;HANDOFF 明示「演示形态」,不冒充生产适配。
- [写确认流在域执行器侧的接线点] → 确认判定在工具注册声明(需确认
  标记),执行器只消费标记——确认逻辑单点在既有确认流,域侧零新机制。
- [凭证误入日志] → 复用 websearch 的凭证脱敏断言测试形态(日志/审计
  grep 断言)。

## Migration Plan

纯增量:api 域包 + mock 脚本;未配置部署零感知(条件注册),无迁移、
无配置项变化面;回退即 revert。
