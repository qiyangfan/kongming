# 设计

## Context

当前接入通过控制面中的可选 `knowledge_search` 工具连接 Siku `/api/search`。它不默认启用，但运行时路径横跨工具注册表、权限点、工具服务、统一出站网关和启动装配。Kongming 自有 RAG 与该工具是不同数据源，移除时必须保留前者。

## Goals / Non-Goals

**Goals:**

- 从可执行代码路径中移除 Siku 工具和端点配置。
- 移除新部署会播种的 Siku 权限点。
- 更新当前规范，防止该接入被当作 Kongming 的既定能力继续扩建。

**Non-Goals:**

- 修改独立 Siku 项目。
- 清除数据库已有的权限行、角色绑定或工具域状态；启动播种遵循只增不改，移除能力后这些历史数据不会再形成可执行工具。
- 改动 Kongming 自有 RAG、文档检索或联网搜索。

## Decisions

1. 删除所有运行时代码中 Siku 专属的配置、工具定义、端口、执行器、白名单注册闸和启动探测。
2. 保留统一工具网关的通用路由能力，以及 websearch、ticket、HTTP connector 等其他域的实现。
3. 删除 Siku 权限点的新部署种子声明；不对已运行数据库执行删除授权的迁移，以免扩大成不可逆的权限数据清理。
4. 将当前 `external-knowledge` 规范改为明确的否定契约；归档提案和迁移说明保持原样作为历史记录。

## Risks / Trade-offs

- 已部署数据库中可能仍有历史 `tool:knowledge:search` 权限行或 `knowledge` 域状态行。没有对应注册项与执行器时它们不产生调用能力；本变更不删除这些数据。
- 未配置 Siku 的默认部署原本看不到该工具；移除主要消除可选配置路径和跨项目耦合。
