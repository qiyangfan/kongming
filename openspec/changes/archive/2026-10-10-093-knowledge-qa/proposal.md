# Proposal

## Why

现行知识分流是**规则词表 + 二选一**:「知识型意图且文档命中」才走 doc_answer,
其余全走 SQL 链路——高价值问题恰恰常需要两者联合作答(「上月退货率为什么
升高」= SQL 算出退货率 + 政策文档解释退货口径),现在只能答一半;词表对
长尾意图(不含「是什么/政策」等触发词的融合问题)必误路由。这是 ADR-010
问答智能体方向登记的知识侧深化缺口,也是问数王牌「从取数到解释」体验闭环
的最后一段。

## What Changes

- 新增 **LLM 意图路由(三态)**:问句在检索前置判定为 数据 / 知识 / 融合
  三态;LLM 路由失败或低置信时回退既有规则词表判定(零回归兜底)。
- 新增 **融合问答路径**:融合态问句同时走 SQL 取数链路与文档检索,由
  融合生成节点联合作答——正文含数据结论与文档口径引用【引用键】,
  复用 068 引用净化与 sources 投影机制;文档未命中时退化为纯数据答
  (零数据副作用纪律延续)。
- **契约放宽**:chat 域「文档道回答的结构化来源」中「SQL 道恒为空」
  调整为「纯数据道为空,融合道可非空」(ADR-005,走 make contracts)。
- **document-rag 分流判定移交**:「知识分流(最小拓扑)」的规则词表
  判定升级为引用 knowledge-qa 域意图路由;doc_answer 保留为纯知识答法。

## Capabilities

### New Capabilities

- `knowledge-qa`: 问答智能体知识链路域——三态意图路由(数据/知识/融合,
  词表兜底)、融合问答生成(SQL 取数 × 文档口径双依据作答)、融合态
  引用净化与来源投影约束。

### Modified Capabilities

- `document-rag`: 「知识分流(最小拓扑)」分流判定由规则词表移交
  knowledge-qa 意图路由(路由失败回退词表,既有 8 节点路径零回归不变)。
- `chat`: 「文档道回答的结构化来源」来源列表约束放宽——纯数据道恒为空、
  融合道由净化后正文单向投影(投影机制本身不变)。

## Non-goals

- **不做多跳/迭代式 Agentic RAG**(自纠检索循环、检索-重写迭代):单轮
  双通道取材已覆盖目标场景,循环式检索留后续演进。
- **不做知识图谱/结构化知识沉淀**:文档道维持父子分块向量检索形态。
- **不改既有 8 节点数据链路行为**:融合为新增旁路节点,数据态问句走
  既有路径逐字不变(零回归纪律延续)。
- **不做融合答专用 web UI 形态**:复用既有消息渲染(正文引用标记 +
  sources + 结果表),web 侧至多按契约生成类型微调。
- **不建融合答评测面**:融合答作为「文本回答」纳入 092 judge 评审对象,
  评估口径由 eval-agent 域承接。
- **不做路由判定的产品化配置面**:路由 prompt 与兜底词表随代码演进,
  不落库配置。

## Impact

- **代码**:apps/agent 问答图新增意图路由与融合生成节点(文档检索经
  既有 api /internal 回调通道,ADR-002 信任边界零变动);apps/api chat
  域响应 sources 语义放宽;apps/web 类型再生成(make contracts,ADR-005)。
- **契约**:chat 响应 `sources` 字段语义扩展(纯增方向:融合道可非空),
  OpenAPI 描述同步,前端类型再生成。
- **schema**:无新表(路由判定计入既有 trace 可观测面,不落新表)。
- **关联**:092 评审对象「文本回答」天然涵盖融合答;document-rag 检索
  与 citation 机制零修改(复用)。
