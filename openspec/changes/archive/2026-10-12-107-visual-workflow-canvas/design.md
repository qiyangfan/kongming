# Design

## Context

- 定义契约已完备:JSON DAG(nodes+depends_on)、「结构校验族」(环/孤立/
  类型/必填配置/on 值)、版本化(同 key 保存即新版本)、租户隔离——全部
  在 api 侧定义端点收口,画布零后端改动即可落地。
- 六类节点的必填配置形态各异(sql 有语句、http 有端点配置、condition 有
  表达式、agent 有目标等),现有编辑页(WorkflowsPage)以 JSON 文本编辑
  为主形态。

## Goals / Non-Goals

**Goals:**

- 画布是「同一契约的第二个编辑视图」:校验/版本化/隔离全部复用,
  转换层纯函数是唯一新增逻辑(可确定性单测)。

**Non-Goals:**

- 自动布局(力导/分层排版)——手工拖拽定位,坐标存于画布态(不进
  定义契约;JSON 无坐标字段,布局是画布私有点)。
- 运行态可视化(执行高亮/进度动画)——执行历史已有分页视图,运行态
  上画布留后续。
- 协作编辑、缩略图导出、子流程封装。
- 节点配置表单的语义升级(字段集与既有必填配置逐一对齐,不加新配置)。

## Decisions

1. **画布库选 React Flow**:拖拽/连线/缩放/选择是画布的全部通用机制,
   自研 SVG 的工作量与质量都不可接受;React Flow 是 React 生态事实标准
   (MIT,纯前端,无服务端),不在技术栈否决清单。新增依赖在
   package.json 显式钉版本。
2. **坐标不进契约**:JSON DAG 定义零变更(方案可比选过「定义加 positions
   字段」——那会改契约并牵动校验/版本化,收益仅是布局持久化,否决)。
   布局坐标存画布本地态(localStorage 按 wf_key+version),换端不迁移
   (可接受:布局是个人偏好不是资产)。
3. **转换层纯函数 + 性质测试**:canvasState ⇄ DAG 互转纯函数,单测断言
   「合法定义往返无损」与「不支持形态显式检出」两类性质;不支持形态的
   判定白名单化(未知节点类型/未知字段检出即回落 JSON 态,fail-safe)。
4. **校验错误定位靠错误文案结构**:定义端点的校验错误已含节点 id(环
   参与节点/非法 on 值场景),画布侧解析同一错误载荷定位高亮——不新增
   服务端错误字段(契约零变更的实现前提)。
5. **condition 分支边即 on 值**:画布语义映射——普通连线=普通依赖,
   condition 出边必须成对指定 on 值(拖线时弹出二选一),从源头杜绝
   「无 on 值条件后继」形态到达服务端。

## Risks / Trade-offs

- [React Flow 引入的包体增量] → 编辑页已是路由级懒加载分包(066 分包
   架构),增量不进入口;版本钉死。
- [画布态与 JSON 态切换的状态一致性] → 单一数据源:编辑态只有一份
   定义对象,画布/JSON 是它的两个投影;切换即重投影,互转纯函数保证
   无损。
- [六类节点配置表单的体量] → 表单字段与既有必填配置一一对齐(无新
   语义),用 shadcn 标准件拼装;分类型组件文件隔离。

## Migration Plan

纯前端增量(新组件+依赖),既有 JSON 编辑形态保留(双态),无迁移;
回退 = revert。
