# Proposal: add-graph-checkpoint(图级检查点与图内挂起)

## Why

`docs/ai-platform-alignment.md` §4/§6 实证了孔明真正的剩余差距:任务恢复粒度是
**步骤级**——步骤内中断(进程重启/挂起)整步重来,已消耗的推理轮次与工具调用全部
重做;人工把关只有两种形态(问数 UX 透明可编辑、计划期 `require_confirm` 挂整步),
**执行图本身的挂起-恢复(第三形态)不存在**——任务循环内的高危动作(如受治理写工具)
当前只能"引导终止循环、留待确认",图状态丢弃。owner 指示按该文档补齐功能缺失,
此项即文档行动表第一行的开工载体。

## What Changes

- **图级检查点**:长程执行图(任务步骤受限 ReAct、协作编排)在每个一致推进点把
  执行状态快照持久化;agent 面零凭证,快照读写 100% 走 `/internal/*` 受控通道
  (ADR-002 既有回调范式),落控制面新表。
- **恢复粒度细化**:中断步骤恢复时优先从最后一次图级快照续跑;快照缺席时回退
  现状(整步重跑),不构成行为回归。
- **图内挂起(HITL 第三形态)**:执行循环内可声明人工确认点;到达确认点图挂起并
  上呈控制面审批,批准后从挂起点精确恢复(非整步重跑),拒绝后按声明跳过或终止;
  审批纪律与 task-kernel 审批门同源(归属人-only、过期未决、幂等)。
- **任务状态映射**:图内挂起使任务进入 AWAITING_APPROVAL 同形语义;挂起/恢复
  事件落既有任务事件时间线。
- **Schema 与契约**:新表走 Alembic 新迁移(ADR-004 约定);`make contracts`
  重生成(ADR-005 管线)。

## Capabilities

### New Capabilities

- `graph-checkpoint`:图级检查点持久化、中断恢复粒度、图内挂起(HITL)及其
  审批生命周期与任务状态映射。覆盖任务步骤执行与协作编排两类长程执行图;
  行为单源,不绑定具体图框架。

### Modified Capabilities

(无——task-kernel 既有审批门/检查点/状态机要求全部保持不变;本能力是其
执行粒度的细化与组合,不改写其行为契约。)

## Impact

- `apps/api`:internal 受控通道新增检查点存取端点;task 域服务扩展挂起-恢复
  交互(既有状态机白名单不扩);新 Alembic 迁移(检查点表)。
- `apps/agent`:检查点存储适配器(存储后端=控制面回调);图装配接入检查点
  与图内确认点原语;业务节点实现零改动。
- `contracts/openapi.json` + web 生成类型:`make contracts` 产物同步。
- `apps/web`:复用既有确认卡形态展示图内挂起,预期极小改动。
- 依赖:不新增任何第三方存储客户端(agent 侧不出现 DB/缓存驱动,import-linter
  继续守护)。

## Non-goals

- **不换运行时**:图框架保留现状(alignment §5 已裁决,含可证伪换向条件)。
- **交互问数图不接入**:请求内 SSE 形态不变,人工把关沿用 UX 透明可编辑形态;
  本能力的挂起只存在于控制面跨请求宿主(任务/协作)上下文。
- **不做时间旅行调试/跨租户快照共享**:快照仅服务同线程恢复,归属严格绑定租户。
- **不改 task-kernel 既有审批门**:计划期 `require_confirm` 步骤级行为逐字不变。
- **不立项 media-generation / 向量规模化**:media-generation 已被 owner 否决
  (2026-10-18,登记 roadmap 否定裁决表);向量规模化(Milvus)另行立项,
  开工先写 ADR。二者均不进本 change。
