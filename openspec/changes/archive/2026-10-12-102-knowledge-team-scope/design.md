# Design

## Context

- team-workspace 已落地:团队/成员(OWNER/MEMBER/VIEWER)/资源归属范式
  (Bot/工作流 team_id NULL=个人)与成员关系查询能力可直接消费(只读,
  该域零改动)。
- 知识条目表 `rag.table_descriptions` 四元唯一
  (tenant_id, datasource_key, schema_name, table_name);检索按
  tenant+datasource 双过滤;检索上下文缓存键 = tenant+datasource+question。
- 语义层登记过一条关联待办:「指标可见性按 data_scope 过滤」(095 登记,
  触发条件=多团队共享数据源上线)——知识归属是其前置步,但不连带。

## Goals / Non-Goals

**Goals:**

- 公共条目行为零回归(不配归属 = 现行为逐字一致)。
- 可见集合单点收敛:条目召回三路、缓存键、管理列表、试跑/覆盖报告、
  历史 few-shot 路全部读写面同一判定纯函数。
- 团队条目在生产召回链路生效:agent 回调透传调用者身份(初版边界
  「agent 零改动」经评审修订,见 Decisions 6)。

**Non-Goals:**

- 指标定义可见性过滤(095 登记待办,后续单独立项)。
- 同表公共/团队双版本与版本合并(单一实例,归属转移原位变更)。
- 行级/列级敏感度分级(团队粒度是本变更边界,更细粒度无真实需求)。
- 数据源级团队共享(数据源归属治理是另一维度,不动)。
- VIEWER 写团队知识(成员关系口径:OWNER/MEMBER 可写,与 team-workspace
  资源可见性同判)。

## Decisions

1. **单一实例而非双版本**:同表两条知识(公共版+团队版)会引入召回
   优先级、覆盖优先级、审计的二维爆炸;归属转移(原位置 NULL⇄team_id)
   表达力足够,治理面简单。
2. **缓存键含团队集合指纹而非 user_id**:键粒度按「可见集合」对齐语义
   (同集合用户共享缓存),比按用户键命中率高、比现键正确;指纹=
   排序后团队 id 拼接哈希(确定性)。团队关系变化 → 指纹变 → 自然隔离
   (旧条目 TTL 过期,无需主动清)。
3. **成员关系校验在 api 侧服务层**(写路径):复用 team-workspace 既有
   成员查询(Protocol 注入),领域规则(可见集合判定)为纯函数——
   Article II 单测形态。
4. **团队删除钩子公共化**:团队删除是既有端点,新增域后置钩子(条目
   team_id 置 NULL + 审计);备选(级联删除知识)毁资产,否决。
   钩子失败不阻塞团队删除(告警 + 条目残留为团队孤儿 → 可见性判定
   按团队不存在=不可见,不泄露)。
5. **fetch-metadata/reindex 的归属语义**:自动来源扫描产出的条目一律
   公共(机器产物不做团队归属推断);团队条目被 reindex 清空重建后
   回到公共——明示在文档与确认文案(reindex 既有「回到自动基线」
   语义的自然延伸)。
6. **调用者身份经回调负载透传(评审期修订)**:初版裁决「apps/agent
   零改动,可见集合在控制面 retrieve 内收敛」保留后半句(过滤/缓存键
   仍在控制面单点),但身份必须随负载可达——RetrieveIn 增可选 `user_id`
   (uuid;缺省 None=纯公共形态,既有负载零回归),agent 侧从入口
   state(chat 请求已写入)透传,一行级改动。备选(维持零改动)使团队
   条目在生产问答链恒不可见,核心场景落空,否决。
7. **历史 few-shot 路同可见集合(评审期并入)**:query_history 样本行
   增 `visible_teams text[]`(来源=回写/晋升时调用者可见集合,空=公共;
   存量回填 '{}' 按公共——来源不可追溯,知识归属启用前无团队来源)。
   召回过滤与条目三路同判据:团队口径 SQL 不经成员授权进入非成员提示段
   (执行历史是团队知识的第二载体,不治理则接线上线即激活泄露旁路)。
   备选(召回时解析 SQL 引用表查归属)依赖 SQL 文本解析,不可靠且贵,否决。

## Risks / Trade-offs

- [缓存命中率下降] → 团队集合少(个人项目)时指纹聚合度高;语义正确
  性优先,量级无虞。
- [可见集合判定泄漏(404 vs 403)] → 非成员统一 404 同形(与既有跨租户
  口径一致),不暴露条目存在性。
- [团队条目被内省对账误删] → 扫描对账(登记=现实)对团队条目同口径
  适用(自动来源对账按四元键,与归属无关)——行为一致,无需特判;
  测试覆盖一条确认。

## Migration Plan

1. 迁移加列(全 NULL,存量=公共,零回归);2. 可见集合纯函数 + 过滤/
   缓存键/管理面接线(测试先行);3. web 表单。回退:revert(列留存
   无害)。
