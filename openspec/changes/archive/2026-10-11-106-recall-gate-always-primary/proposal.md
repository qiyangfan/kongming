# Proposal

## Why

召回闸门的三态机制(off/shadow/primary + shadow 先行建议)是为**生产流量的
阈值标定**服务的:阈值缺省值未知时,必须先影子采分布再定值,灰度是为了不
误伤真实流量。本项目无生产流量,该前提不存在——owner 2026-10-11 裁决:
判断更优即直接切,不保留开关/灰度/影子形态(与 095「默认开启、不做灰度」
的论证同构)。直接切为恒生效的证据已足:阈值标定对拍(2026-10-10)证知识
在位可答题 top1 最低 0.683,对 0.30 阈值有 2.3× 余量零误拒——恒裁不误伤
可答题;收益侧是把「知识不在位还硬凑 SQL」的垃圾生成诚实拦为知识不足路径。
零知识数据源自动旁路(正确性前置,非灰度)保留。

## What Changes

- 闸门恒生效:删除 off/shadow 形态与 `KM_RAG_GATE_MODE` 配置,闸门判定
  (双条件判据)恒以裁剪形态执行——不过闸整路裁掉后重融合,既有
  「知识不足」路径承接,不新增终态。
- 保留不变:双条件判据与按路独立阈值、零命中不投票、全文档路阈值 0
  (该路不裁)、047 继承路同闸、零知识自动旁路、判定与被裁数可观测。
- 试跑端点(064 任务 2.6)同步收敛:删除 `mode` 响应字段与影子措辞,
  verdict/零知识标注(`gate_skipped`)保留——试跑价值收窄为「上传表说明
  后验证可召回性」,不再承载影子期标定。
- trace 观测字段随语义更名(`*_would_drop` → `*_dropped`,语义=被裁数)。

## Capabilities

### New Capabilities

(无)

### Modified Capabilities

- `rag`:「召回相关度闸门」requirement 修订(删三态模式句,恒生效裁剪;
  判据/旁路/可观测约束保留)+「召回试跑」requirement 修订(删影子期
  措辞,试跑语义收窄)。

## Impact

- `apps/api`:rag 域 gate 纯函数(删 mode 分支)、service 配置单点与主链路/
  试跑两处消费、config 删一项;测试改写(off/shadow 用例删除,恒裁语义
  用例改写,既有召回链路测试分数适配)。
- `apps/agent`:零改动;contracts:零变更(试跑端点无 response_model、
  前端零消费,删响应字段无破坏面)。
- `apps/web`:零改动(097 提案工件同步修订,尚未实施)。
- 部署:不再需要 `KM_RAG_GATE_MODE`;已设该变量的部署 MUST 显式清理
  (未知环境变量按既有配置体系忽略,HANDOFF 记录)。
