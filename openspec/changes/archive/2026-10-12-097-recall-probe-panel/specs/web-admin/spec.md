# Spec Delta

## ADDED Requirements

### Requirement: 召回试跑面板

知识库管理页 SHALL 提供只读「召回试跑」面板:输入问句并选择数据源后,调用既有
召回试跑管理端点(与页面同权限口径,不新增权限点),渲染:

1. 三路命中明细——向量 / 全文 / 历史成功 SQL 各路命中的表(含 schema)与该路
   原生分;零命中的路 SHALL 如实展示为空,SHALL NOT 静默隐藏;
2. 闸门判定结论——双条件判定结论(verdict,含判定归因与生效阈值)与被裁
   命中数;闸门恒生效(106 收编,无关闭形态);
3. 零知识旁路标注——数据源无知识时(`gate_skipped=no_knowledge`)SHALL 如实
   标注「闸门未参与(无知识)」,SHALL NOT 呈现为「全部通过」;
4. 关系扩展明细——补入的表、经由的声明关系(源表/目标表/连接键/来源)与扩展后
   表集合;扩展未开启或零扩展时 SHALL 如实展示。

面板 SHALL 零写操作:不修改任何配置、不触发删除/重建类管理操作;空态/错误态/
进行中态 SHALL 用管理面既有标准件(错误 `role=alert`,进行中禁重复提交);
结构化命中列表 SHALL 采用管理面结构化列表标准件双形态(md+ 表格 / md- 卡片,
窄屏横向不溢出)。

#### Scenario: 试跑出三路命中与闸门结论

- **GIVEN** 管理员已打开知识库管理页且持知识管理权限,目标数据源已灌知识
- **WHEN** 输入问句选择数据源后发起试跑
- **THEN** 面板展示三路命中(表名与原生分)与闸门判定结论(verdict 与
  被裁命中数),进行中有 loading 态且按钮不可重复提交

#### Scenario: 零知识数据源如实标注

- **GIVEN** 目标数据源无任何知识条目
- **WHEN** 发起试跑
- **THEN** 面板展示「闸门未参与(无知识)」标注,命中明细仍如实渲染,
  不呈现为闸门通过

#### Scenario: 扩展明细透出

- **GIVEN** 某问句经关系扩展补入 1 张表
- **WHEN** 发起试跑
- **THEN** 扩展明细区展示该补入表、其经由关系(源表/目标表/连接键)与
  扩展后表集合

#### Scenario: 错误态标准件反馈

- **GIVEN** 试跑请求失败(如数据源校验不过)
- **WHEN** 响应返回错误
- **THEN** 面板以既有错误告警标准件展示错误(`role=alert`),既有列表与
  表单不受影响

#### Scenario: 窄屏形态

- **GIVEN** 视口 375px
- **WHEN** 打开试跑面板并出结果
- **THEN** 命中明细以卡片形态呈现,横向不溢出,判定结论与标注可达

#### Scenario: 只读边界

- **GIVEN** 面板任意一次试跑完成
- **WHEN** 检查系统状态
- **THEN** 知识条目、闸门配置、缓存与审计零写入(试跑零副作用由端点既有
  契约保证,面板不提供任何写操作入口)
