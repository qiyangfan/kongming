# 071-understand-dialogue-reply-passthrough 提案:纯对话复语不进取数补全

## Why

`understand` 节点(`graph/nodes.py:53`)在每一轮都先做一次 LLM 改写;多轮形态下
`UNDERSTAND_MULTI_SYSTEM`(`graph/prompts.py:29`)的命令是无条件的:
「结合历史问题,把当前问题补全为一个**独立、清晰、可独立理解的查询意图**」。

于是"不用了 / 取消 / 算了 / 好的 / 谢谢"这类**不携带任何取数意图的对话复语**,
会被强行补全成一条完整查询——补全的素材只能来自上一轮问句,结果就是
**把用户上一轮的问题连同其全部限定条件复述成"本轮的新问题"并真的去检索、生成、执行**。

用户看到的是一屏与他的"不用了"毫无关系的结果表;代价是一次 UNDERSTAND 调用 +
一次 embedding 调用 + 两路召回 SQL + 一次 SQL 生成调用 +(命中时)一次真实执行。

### 上游为这一条留了一手事故证据

参考问答线在同位置有一条明文硬闸:**当输入规范化后等于纯对话回复词
(否定/终止/确认/应答家族)时,禁止改写**。其代码注释记录的真实事故是——
`"取消"` 被扩写成 `"取消切换逆变器 X 为备电模式"`,绕过了对话控制面并
**重新触发了一次 `work_mode_switch` 写操作**;`"确认"` 复活了一张已处理的操作卡。

本仓的暴露面确实比它小,这条差异要说清楚,不夸大:recipe 道无写工具,
写确认走 `/chat/tool-confirm` 带外通道(不经 LLM),ReAct 道拿的是原始 history
不经 `understand`。**所以本变更的理由不是"会误触发写",而是三条更朴素的**:
①把用户没问的问题真的执行了一遍(行为错误);②白烧一轮 LLM + 检索 + 执行(成本);
③改写器在"必须补全成查询"的指令下,对任何非查询输入都会臆造——这是
提示词指令本身制造的幻觉面,不是模型的偶发失误。

## What Changes

1. **`understand` 前置一道零模型调用的直通判定**:当前问句规范化后
   (去首尾与内部空白、去中英文句读、拉丁字母小写)**全等于**闭合复语词表成员时,
   SHALL NOT 发起改写调用,SHALL NOT 进入检索与生成。
2. **复语轮次按既有中性终态收敛**:SHALL NOT 新增终态、SHALL NOT 改响应信封
   (复用现有第四态语义,与 064 的"零命中不新增终态"同一处置口径)。
3. **词表是闭合常量、全等匹配**:
   - 覆盖三类——否定/终止(不用了/不需要/不必/算了/取消/终止/停/no/nope/cancel/never mind)、
     应答/致谢(好的/好/知道了/明白/收到/谢谢/多谢/thanks/thank you/got it/ok/okay)、
     招呼(你好/您好/hi/hello/hey);
   - **SHALL NOT 用包含或前缀匹配**——"取消订单""确认切换工作模式""停掉库存不足的门店的
     促销"这类真实问法必须照常补全。上游同样刻意只做全等,理由一致;
   - 词表随代码发布,**不做管理台热配**。
4. **不做的事**:不裁决"该不该继续上一轮"(复语轮次直接收敛,不猜测指代);
   不改 `UNDERSTAND_MULTI_SYSTEM` 的保真规则与聚合口径规则(048 资产逐字不动)。
5. 该轮次 SHALL 计入可观测(复语直通命中数),以便词表宽严有据可调而不是拍脑袋。

## Non-goals

- **不做闲聊应答道 / 招呼的拟人回复**("不客气,还需要看别的吗"之类)。
  那是一条新的产品分流能力,涉及文案、是否允许无数据回答、计量口径,须独立提案;
  本变更只保证**不把复语伪造成查询、不执行、不烧调用**。收敛文案沿用既有第四态,
  对致谢类不算愉悦但严格优于现状(现状是给用户一屏没问过的数据)。
- **不改 `understand` 的补全质量与保真规则**(018/048 资产与契约不动)。
- **不给 ReAct 内核加该判定**:ReAct 不经 `understand`,且工具调用由模型决策,
  复语在那条路径上不会变成执行。
- **不做语义化的"这是不是数据问题"分类器**(引模型调用判非查询,与本变更
  "省一次调用"的动机相反)。
- **不改四态语义与响应信封**(ADR-005 零触发);**无 schema 变更**(ADR-004)。

## Capabilities

### Added Capabilities

- nl2sql-agent:新增「对话复语不进补全」Requirement——不携带取数意图的闭合复语词
  SHALL 在改写前全等识别并直通,零模型调用、零检索、零执行,按既有中性终态收敛。

## Impact

- **落点**:仅 `apps/agent`——`graph/nodes.py:understand`(前置纯函数判定 + 直通分支)、
  新增或就近一个闭合词表常量(纯数据,零依赖)。
- **路由**:`understand → retrieve` 现为**无条件边**(`graph/build.py:89`),需改为条件边
  以承载直通出口(与 043 把 `generate → validate` 改条件边同一形态);短路出口
  复用既有 `end_reason` 收敛通路(→ 第四态),不新增终态取值。
  `tests/test_graph_topology.py` 须同步断言"复语轮不进 retrieve/generate",
  并维持既有铁律(任何重试必经 `selfheal`)不被新边破坏。
- **无契约变更**(ADR-005):响应字段与终态取值集合零改动。
- **无信任边界变更**(ADR-002):agent 面本就零凭证,判定是纯字符串比较。
- **成本口径**:与 062 的方向一致(少一次无意义调用),但本变更不引入任何配额/限流机制,
  两者无依赖、无重叠。
