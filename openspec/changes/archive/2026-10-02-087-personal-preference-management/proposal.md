# 087：补齐本人偏好的查看、修改与清空

## Why

偏好会持续影响后续回答，用户必须能纠正或撤销。`agent-memory` 已规定本人可查看、编辑、清空，但 `MemoryPage` 只管理自由文本记忆。现有 `PUT /memory/prefs` 过滤 null，归一化再丢弃空字符串和空列表，最后合并旧值，因此无法删除一个槽位或清空整份偏好。

仅补页面无法完成清空；现有后台提取还可能在用户修改后写回旧值。本件同时补齐显式管理语义和必要的并发保护。

## What Changes

- 沿用本人当前租户的 `GET/PUT /memory/prefs`，PUT 省略字段保留，显式 null 删除该字段；新增同路径 DELETE 清空全部偏好。
- 在现有记忆页面增加偏好区，提供查看、编辑、逐项清除和全部清空。
- 人工操作使用短事务合并，并增加一个内部人工修改版本；旧问答的自动提取不得覆盖或复活之后的人工作业。
- 保留七个既有槽位、`{prefs: {...}}` 响应与既有认证、租户边界；类型仍由契约生成。

## Capabilities

### Modified Capabilities

- `agent-memory`：补齐偏好自管理与并发写入边界。

## Non-goals

- 不增加第二套记忆存储、历史版本、偏好市场或永久关闭学习开关。
- 不改变 NOTE、团队记忆、业务数据权限和 SQL 数据范围。
- 不把自由字符串槽位改成未经契约约定的枚举。
- 收款继续 Mock；不接入真实支付渠道。

## Impact

- 控制面 memory 域、问答准备与后台记忆任务、MemoryPage、契约生成物。
- 用新的迁移增加内部版本字段，不改历史迁移或现有 JSON 列类型。
- 依据 ADR-004（schema 演进）、ADR-005（契约生成）、ADR-002（控制面持数据）执行；无需改变进程信任边界。
- 接续历史 059 的前端遗留项；历史归档件保留，本件实施前不宣称遗留已完成。
