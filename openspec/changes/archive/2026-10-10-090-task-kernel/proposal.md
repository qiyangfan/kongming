# Proposal: 开放式任务内核

## Why

通用智能体与问数助手的分水岭是**长任务**:现在的自主性上限是「一轮 ReAct(轮次上限 ≤10)+ 会话内 Todo 账本」,任务随请求生灭;Manus 式「给目标、后台跑、随时看」需要任务成为**跨请求的持久一等实体**——可分解、可检查点、可暂停/恢复/取消、可在高危步骤前挂起等人审。这是通用多领域智能体的执行内核,也是多智能体协作(091)的宿主。

## What Changes

- 新增任务实体:目标 + 状态机(PLANNING/RUNNING/AWAITING_APPROVAL/PAUSED/DONE/FAILED/CANCELLED,VARCHAR+CHECK)+ 归属(user/tenant),任务可关联发起会话。
- 计划与步骤:任务分解为持久步骤清单(每步目标/状态/证据引用/失败原因),步骤状态由工具执行结果驱动——继承「有证据才完成」与「预算退出诚实」原则到跨请求语义。
- 检查点与恢复:每步终态后落检查点;任务可从最后完成的步骤恢复继续;进程重启后 RUNNING 任务标记为中断态,可手动恢复,SHALL NOT 静默假装完成。
- 审批门:步骤声明 require_confirm 时任务进入 AWAITING_APPROVAL 挂起,复用既有写工具人工确认流的归属校验/幂等/过期语义;批准继续、拒绝按策略跳过或终止。
- 任务级预算:步数/token/时长三约束,耗尽 → PAUSED 且部分完成如实披露;任务执行的一切工具调用走既有回调与防御(ADR-002 零改动)。
- 任务观测:任务事件(创建/计划/步骤迁移/审批/终态)挂同一任务 trace 语义,进既有 trace 时间线;用量按任务维度归集。
- 任务 API 与最小前端面:列表/详情(计划与步骤进度)/暂停/恢复/取消。

## Capabilities

### New Capabilities

- `task-kernel`: 跨请求持久自主任务的生命周期、计划与步骤、检查点恢复、审批门、预算与观测的全部行为契约。

### Modified Capabilities

(无——ReAct 会话内 Todo 账本行为不变,任务是账本的跨请求上位形态,两条链路并存不互改。)

## Impact

- `apps/api`:新域包 `task/`(任务/步骤持久化、状态机、审批门、恢复调度),复用既有写确认流与审计;权限点 task:create/read/manage(测试先行)。
- 数据库:新 Alembic 迁移建任务两表(ADR-004/VI:UUID v7、VARCHAR+CHECK、timestamptz;已规划列一次建全)。
- `apps/agent`:任务驱动执行循环(目标→计划→逐步执行→检查点),执行仍 100% 经既有工具回调,零凭证不变(ADR-002)。
- 契约:新增任务公开端点,`make contracts` 重生成(ADR-005)。
- `apps/web`:任务列表/详情页(标准件、DataView 双形态、移动优先)。

## Non-goals

- 定时/事件触发式任务创建——与 triggers-webhooks(032)的桥接是独立变更。
- 多智能体派发与协作拓扑——091 的范围;本变更的任务步骤执行者恒为单 ReAct 内核。
- 跨租户共享任务/任务模板市场/任务导出——后续产品决策。
- 任务并行多步执行(v1 步骤串行,并行属 091 协作语义)。
- 会话内 Todo 账本改造——既有行为零改动。
