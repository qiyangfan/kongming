# Design

## Context

111 实证否决「无差别任一词条 OR 兜底」后,已知缺口=中文自然问句虚词断裂
的全文路零命中(xfail known-issue)。111 的失败机理已被精确定位:单字
虚词/量词词条(『有』『部』)高频命中无关表说明,且 ts_rank 量纲无法区分
内容词与虚词命中。rag spec 现行条款点名改善路径=「带内容词过滤的形态,
另行提案+同指纹 A/B 实证」。本变更即该路径的最小实现与终局验证。

## Goals / Non-Goals

**Goals:**

- 兜底轮只允许内容词(长度 ≥2)参与匹配,从谓词上排除 111 的劣化输入
- 两态闭环:采纳=spec 场景兑现+摘 xfail;回退=二次否决封档——无论成败
  不留「待提案」悬案
- 验收线在提案期钉死,评估后不移动门柱

**Non-Goals:**

- 不动 AND 轮(整句全词条 plainto_tsquery 保持——AND 命中的题零影响,
  这是风险有界性的来源)
- 不做 zhparser 自定义停用词典(备选方案 Y,见 D2)
- 不调 064 fulltext 闸门阈值(备选方案 Z,见 D2)
- 不引入词性标注/IDF 等超出 SQL 内建能力的相关性机制

## Decisions

**D1 内容词判定=length(tok) >= 2(单谓词,不做词表)。**中文语言学近似:
单字多为虚词/量词/高频泛指(『有』『部』『多』),双字以上多为内容词
(『影片』『库存』『租出』)。误滤单字内容词(『租』『买』)的代价=该
词条不参与**兜底轮**(AND 轮不受影响),表说明检索场景双字词覆盖绝大多
数检索意图。不用停用词表:清单是长期内容资产,质量决定效果,维护面与
收益不成比例。

**D2 方案比较(备选均否决)。**
- *Y:zhparser 自定义停用词典*——需容器内维护词典文件+重载+两库同步,
  部署面膨胀,清单质量=新长尾问题;且停用词过滤作用于**写入侧 tsv** 时
  会改变存量向量形态(触发全量重扫),作用域大于问题(兜底轮),否决。
- *Z:064 fulltext 闸门阈值裁剪兜底行*——zhparser 量纲未标定(HANDOFF
  载明),探针实证内容词命中行与噪声行分数同量纲(部分内容词行 ≈0 分),
  阈值必然误伤内容词命中,治标不治根,否决。
- *X(采纳):兜底谓词内容词过滤*——一处谓词、零部署面、直击 111 定位
  的根因、最坏情况=基线,复杂度/性能/迁移/维护全维度最小。

**D3 缓存键语义段 `and-cw`。**与 098 配置段/102 指纹段同一键版本化思路;
本变更与 111 期间(曾用 `and-or` 段)及回退态(无段)三种键空间互不可见,
TTL 窗口自然隔离,无残留串味。

**D4 测试策略。**沿用 111 验证过的形态:对拍桩钉轮次纪律与谓词字面量
(过滤条件进期望 SQL);摘除 xfail(strict 转真跑,兜底生效即绿);恢复
「有多少部影片」兜底集成测试(表说明+文档路);单字词条被滤的负证集成
断言(『有』『部』命中的噪声表不再进兜底轮)。

**D5 验收协议。**B' 轮前清 query_history 与 ragctx 缓存(与 A 轮口径对
齐);采纳线=严格 ≥32 ∧ 表命中 ≥46 ∧ 宽松 ≥48 ∧ 探针机制兑现;
逐项持平亦采纳(纯增能力+场景兑现);任一项越线→回退,spec 落二次
否决封档(known-issue 定格终态),两态皆归档闭环。

**D6 判定记录与 111 勘误(终局)。**B' 净轮 49/32/45:失败名单与 A 轮
逐题一致(olist_016 波动+35ced065 FILTER+两道 hex id 题 403),表命中
-1 经两路检验定为采样波动——①表命中判据为子集语义
(`expected_tables.issubset(gen_tables)`),兜底轮只会增召回面、无「缺表」
因果路径;②B'' 轮(同代码)表命中回升。调查中发现并修复两个**评估基建
缺陷**(它们才是历轮分数噪声的真源):
- **日配额耗尽污染**:`chat_quota_daily_calls` 缺省 500 按 (租户,日)
  累计,A 轮(当日首轮)耗掉大头后,111 B 轮中段起撞线、B' 首轮全拒
  (429 CHAT_QUOTA_EXCEEDED)——**变更 111 当时的「三指标各 -4 系统性
  劣化」结论系此事故误判,兜底机制从未被有效评估**;逐题日志显示 B 轮
  8 题失败中 7 题为 429/403 异常。评估环境常备配方补
  `KM_CHAT_QUOTA_DAILY_CALLS=0`(0=不限)。111 已归档工件(design D6)
  为历史快照不回改,勘误以本节+evals/README 为准。
- **hex id 题租户推断 403**:evals `_tenant_of` 按 `id.split("_")[0]`
  推断,hex id 题(6183fe4b/381c7e34)推出不存在的租户→恒 403——
  **四轮基线(含 zhparser A 轮 49/32/46)都含这 2 题恒异常失败**;
  sakila.yaml 补显式 `tenant: sakila` 后首次真实判定(6183fe4b 通过、
  381c7e34 真实判负)。
B'' 轮(修复后):50/34/47 创新高,失败 3 题全确定性 FILTER 归因;
对齐口径(hex 两题按 A 轮恒失败计)49/33/46——三项 ≥A 轮,**采纳**。

## Risks / Trade-offs

- **双字词噪声仍存在**(如『信息』『数据』类泛内容词):命中频率远低于
  单字虚词,且 ORDER BY ts_rank(命中词条多者分高)继续压低;B' 轮 evals
  为最终判据,越线即回退。
- **英文短虚词(of/to/in,长度 2)不被过滤**:缺省 simple 档英文题受
  影响面与 111 相同且已有基线数据对照;长度启发式是中文形态的针对性
  修复,不为英文扩展启发面(YAGNI)。
- **评估采样波动**:olist_016 已知波动题在验收线中显式容差(-1);
  表命中/严格为确定性判据不容差。
