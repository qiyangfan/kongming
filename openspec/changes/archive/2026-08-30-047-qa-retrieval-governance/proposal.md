# Feat: 047 问答链路检索治理与多轮质量修复

## Why

2026-08-30 全链路冒烟(评估 48 单轮 + 12 多轮 + 浏览器定向)发现多轮 -25pp
回归(9/12,基线 12/12)与两个产品级问题,逐题溯源五挂全部闭环,机制如下:

1. **便捷视图入知识(根因级)**:内省双处(rag fetch-metadata + internal meta)
   `table_type IN ('BASE TABLE','VIEW')` 把 sakila 便捷视图连同样例 SQL 收进
   表结构知识(08-23 AI 再生成)。视图是基表派生物且行扇出失真
   (film_list 一片多行,AVG(price) 被库存份数加权,3.1 vs 3.13 实证;
   customer_list 无 email 列而模型照用,执行失败实证);视图条目带聚合示例
   在召回里与真问题竞争,挤占维度表 top-K(sakila_021 召回集缺 category
   维度表、视图"捷径"形态挤入,模型在失真 SQL 与误判 NO_DATA 间摇摆)。
2. **多轮检索不继承上轮表集**:追问改写问句单独召回,行为表被回答词主导
   挤出 top-K(sakila_mt_005 召回缺 rental,模型 JOIN 清单外表+清单外列)。
3. **文档分流被泛系系词劫持**:多轮追问「这些影片各自的分类是什么」仅命中
   「是什么」即被分流 doc_answer(文档在场即命中),用户拿数据追问得到
   「文档中未提及」(浏览器实测复现)。
4. **自愈喂回无分类**:missing FROM-clause 类机械错只回「请修正」,模型同因
   连败两轮(sakila_017 引用未 JOIN 别名 s,重试 2 次同错)。
5. **建议缓存不随治理失效**:039 缓存只挂数据源连接变更;045 收编保留表后,
   default 源存量建议仍是「用户记忆」撞墙题 3/5(浏览器实测复现)。
6. **verdict 文案责备用户/裸露技术细节**:REJECTED(RESERVED_TABLE)文案
   「该查询访问了不允许的表」把模型越界说成用户之过;FAILED 把 PG 原始
   报错(`missing FROM-clause entry for table "s"`)裸露给用户。

另外:08-23 知识再生成与文档灌入均晚于 08-22 评估基线,本次对比被环境混杂
——基线纪律缺「知识库/文档变更后须重跑评估」条款,须补齐并重立基线。

## What Changes

- **知识治理**:内省两处(rag `_introspect_all_on`、internal meta)收窄为
  仅 `BASE TABLE`——视图不进表结构知识;存量视图条目由 042 对账语义在
  下次 fetch-metadata 自动清偿(自动来源孤儿删除,登记=现实);
- **多轮检索继承**:内部召回端点与 `RagService.recall` 增可选 history,
  对最近一条历史问句独立召回一路、去重合并(主路优先、总量封顶),
  ctx 缓存键并入历史指纹;agent retrieve 节点透传最近 3 条历史;
- **文档分流门槛**:多轮会话(history 非空)且仅泛系系词「是什么」命中
  意图词表时不分流文档,回 generate;强文档词(政策/流程/制度等)照旧;
- **自愈喂回分类**:`_selfheal_guidance` 纯函数按 PG 错误形态(missing
  FROM-clause / 列不存在 / 表不存在)生成针对性修正指令,generate 复用;
- **建议缓存治理失效**:rag 知识写路径(upload/edit/delete/fetch-metadata/
  reindex)同事务级联失效该数据源建议缓存(新窄端口,与 datasource 域
  SuggestionCacheEvictor 同范式);
- **verdict 文案用户化**:RESERVED_TABLE 分态文案中性化;FAILED 文案改
  用户语言,原始错误迁移新契约字段 `error_detail`(纯增),web 折叠展示
  「技术详情」;
- **评估重立基线**:修复后重跑 smoke/full/multiturn,README 记录基线行,
  基线纪律补「知识库/文档增删后须重跑评估」。

## 决策摘要(架构师裁决)

- **否决「视图降权保留+禁聚合示例」**:排除比治理简单且彻底——视图可被
  基表完整表达(视图即基表查询别名),保留即保留歧义;治理样例质量是
  开放式内容审核问题,不可判定、不可回归测试;
- **否决「召回层过滤视图/保留表」**:毒性在收录层,过滤在召回层=每个消费
  方各自设防;042「登记=现实」对账是既有清偿机制,收录收窄后重跑扫描即
  自动清偿,零新增清理代码;
- **多轮继承否决「检索词拼接 history」**(稀释向量语义、不可测)与
  「api 从历史消息 SQL 提取表集」(persist=false 通道无消息可提,跨层
  泄漏 SQL 语义进召回端口)——双路召回合并是确定性继承,端口只加可选
  history 列表,分层不破;
- **文档分流否决「指代词表否决」**(词表弱信号教训:036 已两犯)——用
  「历史在场提高门槛」的结构性条件:单轮 024 语义零改动,多轮仅降档
  泛系系词;
- **FAILED 技术细节否决「api 侧截断/翻译 PG 错误」**(翻译不可穷举,
  截断丢排障信息)——用户语言进 `error`、原始错误进 `error_detail`,
  web 折叠展示,两全。

## Capabilities

### New Capabilities

(无)

### Modified Capabilities

- `knowledge`:内省收录范围收窄为基表(视图不入知识);知识写路径级联
  失效建议缓存;
- `internal-meta`:实时内省范围同步收窄为基表(与 knowledge 同口径);
- `nl2sql-agent`:多轮召回历史继承;文档分流多轮门槛;selfheal 分类喂回;
- `chat`:REJECTED/FAILED 文案用户化;`error_detail` 契约纯增;
- `chat-suggestions`:缓存生命周期增加知识变更级联失效;
- `eval`:基线纪律补知识/文档变更触发条款(基线行随实施更新)。

## Non-goals

- ReAct 工具链路的 history 透传:rag_retrieve 工具语义自包含(LLM 自行
  组织查询),多轮主链路(8 节点图)先收口,ReAct 等价性另测;
- 视图「白名单放行」配置:当前无业务场景需要视图进生成知识,不为假想
  需求建开关;外部库真有仅视图可答的形态时按需另立变更;
- 建议问题内容级过滤(对产出文本做保留表名词屏蔽):digest 已滤保留表,
  存量缓存由级联失效清偿,双层防线属过度设计;
- 存量消息 error 文案的迁移改写:落库历史消息按写入时文案回显(005 形态
  由 `_to_message` 兜底的先例同款),不刷数据;
- AI 润色产出的「unknown」类型前缀清洗:实测未见生成面危害,不扩范围。
