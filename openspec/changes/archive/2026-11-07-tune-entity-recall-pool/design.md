# Design: tune-entity-recall-pool

## Context

- A/B 数据:实体关 1.000 / 实体开 0.938(同环境同条件,16 题);唯一系统性
  漏跳=retr_sakila_002,probe 归因=实体路 6 候选全部由「逾期费」单实体
  join 而来,挤占融合池后正确父块跌出 top-5。
- 首版 join 语义:任意查询实体命中即入池(OR 语义)。词法兜底按 OR 习语
  设计(098 中文 AND 压制同款),叠加泛频实体即放大为整池挤占。
- 门槛语义与 SAG 动态超边定义对齐:超边由**多实体共享**实例化;单实体
  命中退化为普通词法共现,其召回职责已由向量/全文两路承担。

## Goals / Non-Goals

**Goals:**

- 消除单实体挤池形态:实体关/实体开两形态分数不再系统性背离(对照红线
  口径下实体开不劣于实体关)。
- 门槛语义进 spec 与测试,防止后续回退为 OR 全量并入。

**Non-Goals:**

- 不追求实体开在本语料上超越实体关(语料偏小+embedding 强,基线近天花板,
  多跳题已被两路覆盖;实体路价值留给更大语料/更难跳型,不构成本变更验收)。

## Decisions

### D1: 门槛=共享查询实体数 ≥2,仓库层 HAVING 过滤

`recall_children_by_entities` 增加 `min_shared`(服务层常量注入,缺省 2):
`HAVING count(*) >= :min_shared`。count(*) 在 (chunk_id, name_normalized)
唯一约束下恰=该子块命中的去重查询实体数,语义精确。选择仓库层而非服务层
过滤:join 溢出在 SQL 侧截断,不传输注定丢弃的行。
备选(服务层 post-filter)否决:多传 6 行只为丢 6 行,且逐路展示要再剔一次。

### D2: 合并实体数 <2 时整路短路(不 join、不识别)

查询实体集(LLM 识别 ∪ 词法兜底)规模 <2 时直接返回空:门槛已注定空结果,
短路省一次 LLM 识别后的 join 查询。LLM 识别本身仍执行(识别失败降级词法
的语义链不变);「识别+词法合计 <2」= 该问句无桥接形态,整路静默为空。
备选(先识别后决定是否调词法)否决:词法与识别是并集互补关系,短路条件
只能看合并结果,拆开执行顺序不成立。

### D3: 门槛为域常量,不做部署级配置

共享实体数 ≥2 是超边语义的定义边界(「≥1」即回退首版形态,「≥3」在
8 实体配额下桥接覆盖过窄),不是运营调参面;进 config 反而暗示可随意动。
常量+注释+测试三重钉死。备选(KM_DOC_ENTITY_MIN_SHARED)否决:配置面
只收真实需要部署间差异的项(对照 query_max 的截断配额)。

### D4: 验收=同环境同条件复测对照,红线口径不变

调优后实体开复跑 retrieval 层评测(同语料同题集同 LLM 端点),结果进
README 基线表新行。判据:宏观 Recall@5 不低于实体关行(允许边界题 012
类采样翻转,逐题溯源豁免口径同前);002 恢复命中(probe 复核实体路为空
或不再挤池)。复测仍系统性劣化(≥5pp)→ 按owner 指令转下掉处置
(扩展路移除为独立变更,本变更不混合交付)。

## Risks / Trade-offs

- [双实体同概念的假桥接(如「逾期费/逾期费率」)可能漏并真实桥接块] →
  门槛取向=精确优先:错并的代价(挤池)已在实测中显性化,漏并的代价
  (少一路补充)与既有两路降级同形态;逐路试跑可见,不静默。
- [LLM 识别实体数波动影响短路判定] → 词法兜底并集兜底识别抖动;门槛
  判定在合并集上,单路抖动不翻整路空/非空(除非合计恰在 1/2 边界)。

## Migration Plan

零迁移零契约变化;部署升到含本调优版本即生效(实体开关缺省关的部署零
感知)。回滚=还原两处检索代码,伴表与抽取面不回滚。
