# 文档关键词排序 BM25 对照评测

## Why

孔明用向量找语义相近的段落，也用关键词匹配原文，关键词结果目前按 PostgreSQL 的 `ts_rank` 排序。需要用自己的文档和题目确认，换成 BM25 后，产品牌号、标准编号和业务术语能否更容易找到对应原文，以及检索耗时会怎么变化。

## What Changes

- 比较「向量 + `ts_rank`」和「向量 + BM25」。两组共用相同的原文、分词、关键词匹配规则和结果合并方式，只替换关键词排序。
- 复用现有文档检索评测，补充牌号、编号、中文术语、同义改写和需要多段证据的题目。报告逐题给出前 5 条结果是否覆盖必需原文，也记录耗时。
- 在评测前固定题集和判定条件。根据实测结果给出是否值得另立生产接入提案的建议。

### New Capabilities

### Modified Capabilities

- `retrieval-eval` 增加两种关键词排序的对照运行、资料范围检查和结果判定。

## Impact

- 按 ADR-010 归入评测智能体方向，服务文档问答。评测在 `apps/api/evals/retrieval/` 中独立运行，沿用现有文档检索试跑接口和评测租户的数据源。
- 按 ADR-002，实验排序只在隔离评测环境的 API 进程执行。资料和词频统计都限定在所选评测租户和数据源内。
- 本提案比较同一批原文的关键词排序。`evaluate-wiki-document-qa` 比较主题页与原文取材，两份评测可独立运行。

## Non-goals

- 生产检索切换、两套关键词排序同时参与结果合并、Wiki 检索接入。
- 新增搜索服务、生产依赖、对外接口或数据库结构变更。
