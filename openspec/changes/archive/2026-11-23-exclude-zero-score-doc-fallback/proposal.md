# 文档全文兜底轮零分命中不参与融合

## Why

真实公开文档(K8s 73 篇)诊断暴露:文档全文路在 AND 零命中时进入内容词兜底轮,
兜底轮谓词是「任一内容词命中」,但计分仍用**全问句** ts_rank——按 PostgreSQL
语义,缺词问句的部分命中分约为 1e-20(实测;全词命中约 0.1),等于全为 0 分,
名次是任意顺序。这些 0 分候选按 RRF 名次进入融合,把向量路已命中的父块挤出
top-5:30 题真实语料中 `k8s_s_01`(向量路命中 Pod#0、融合丢)、`k8s_c_02`
(卷#4 在向量候选内、融合丢)是直接证据。合成语料上全文路 Recall 恰等于
AND-only 命中数(0.162=12/74、0.071=2/28),兜底轮从未贡献可验证召回,只贡献
无序噪声。

## What Changes

- 文档全文兜底轮(OR 谓词轮)只保留正分命中:全问句 ts_rank 低于 1e-9 的命中
  视为无词面证据,不再返回、不进入 RRF 融合与试跑逐路。
- AND 轮行为不变;BM25 排序变体正分命中不受影响。
- schema(表说明)全文路的兜底语义不变,本变更只收敛文档通道。

## Impact

- 文档检索融合结果变化(预期为剔除噪声后向向量路靠拢);接口、返回结构、
  引用键与缓存键不变。
- 评测:K8s 30 题应恢复融合稀释丢跳;15 文档/lab 74/判别语料按红线复核。

## Non-goals

- 不改 schema 表说明路的 AND/兜底语义与闸门。
- 不改分词配置、child/parent top-k、RRF 函数与精排/BM25 排序实现。
- 不调整兜底轮谓词(仍为「任一内容词命中」)与单字排除规则。
- 不改试跑接口结构;仅兜底轮零分命中不再出现在结果中。
