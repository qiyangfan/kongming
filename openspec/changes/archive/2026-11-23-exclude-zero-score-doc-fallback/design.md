# 设计:文档全文兜底轮零分命中剔除

## 上下文

- 文档全文两轮:AND 轮(全词条)零命中后落内容词兜底轮;兜底谓词按词条
  EXISTS,但排序与得分沿用全问句 `ts_rank`。
- 实测(PostgreSQL):缺词问句的部分命中 `ts_rank ≈ 1e-20`,全词命中约 0.1;
  兜底轮的候选必然缺词,故全部为 0 分量级,排序无意义。
- 融合(RRF)按名次取候选,0 分无序候选会挤占向量路有效命中。

## 决策

1. 在仓储层单点过滤:`recall_children_fulltext` 的兜底轮返回前,剔除
   `score < 1e-9` 的命中(常量与依据写入注释)。AND 轮不过滤(全词命中分正常)。
2. 阈值取 1e-9:实测部分命中 1e-20 与全词 0.1 之间留足数量级;若未来
   PostgreSQL 改变计分下限,高于阈值的兜底命中本身已具备排序意义,放行无碍。
3. 过滤发生在仓储出口,融合、精排、试跑与缓存自动一致;BM25 变体兜底命中
   为正分,不受影响。
4. 不引入配置开关:规则是「零分词面证据」的语义修正,无双轨价值。

## 验收口径(运行前登记)

- K8s 30 题:融合 Recall@5 由 0.783 提升(预登记 ≥0.80),`k8s_s_01` 恢复命中;
  `k8s_c_02` 至少恢复一跳;全文路 Recall 不下降(AND 命中不受影响)。
- 回归红线:15 文档 28 题 ≥0.914(5pp 内);实验室 74 题与判别语料 74 题
  ≥0.950(均以 1.000 为基线)。任一越线即回退。
- 行为等价:接口结构、父块正文、引用键、向量维度不变。

## 风险与回滚

- 风险:某语料中兜底轮曾以「任意顺序」带来幸运命中,剔除后可能丢失;
  合成与真实语料实测兜底轮均未贡献可验证召回,回归红线覆盖此风险。
- 回滚=回退该过滤代码,无需数据重建(索引不变)。
