# 089-eval-failure-attribution 提案:评估失败归因分类

## Why

孔明的质量闭环目前只有一个数字:Execution Match(宽松/严格)。失败之后没有任何
结构化归因——`evals/test_eval.py` 的失败明细是自由文本(gold/gen SQL + 前三行),
要人肉逐题读。后果有三:

1. **无法回答「该修哪一层」**。选表漏召回、JOIN 拍错、指标口径错、谓词/时间窗
   错、被防火墙拦、执行炸,六类问题的修复动作完全不同(改知识/改关系配置/改
   指标定义/改 prompt/改防火墙),现在只能靠读 SQL 猜。
2. **立项靠文章,不靠数据**。本次 088(关系感知召回扩展)的触发点是一篇 Medium
   文章;如果失败归因显示选表/JOIN 类占比极低,这个提案根本不值得做。归因是
   把质量决策从「读文章」改成「读自己的评估集」的基础设施——这也正是对该文章
   最有力的回应方式:用它自己的数据口径检验它。
3. **分类必须诚实**。确定性判据不可能覆盖所有失败形态,所以必须保留显式的
   「未归因」桶,并规定占比过高时扩充规则——禁止让启发式分类 quiet 吸收现实
   (与 064「SHALL NOT 静默降质」同源纪律)。

判据设计:只用评估器**已有**的确定性信号(gold/gen SQL 文本、执行结果集、
链路 verdict、既有抽表能力),不上 LLM 分类(LLM 分类自己就会错,且不可复现);
不引入新依赖;分类为纯函数,进默认测试门禁。

## What Changes

1. **新增失败归因纯函数模块**(`apps/api/evals/attribution.py`):入参=失败题的
   既有产物(question / gold_sql / gen_sql / gold 与 gen 列行 / 链路 verdict /
   涉及表集合),输出=唯一一级分类 + 层拆分信号(仅 SELECT)+ 判据原文 + 原始信号。
2. **一级分类(优先级序固定,先匹配先归类,一题一类)**:
   - `NEG_GUARD` 负例/拒绝守护失效(`expect_reject`/`expect_no_data` 用例失败
     即此类,不再细分);
   - `EXEC` 生成 SQL 执行失败(含 selfheal 耗尽);
   - `REJECT` 生成 SQL 被 SQL 防火墙拦截终止(verdict=BLOCKED);
   - `ABSTAIN` 误弃答(正例题链路返回 NO_DATA);
   - `SELECT` 选表缺失——附层拆分:期望表未覆盖(=召回层)或 gold 表集未覆盖
     (=生成层);
   - `JOIN` 关联缺失(表齐但 gen 的 JOIN 数少于 gold);
   - `METRIC` 口径/聚合差异(表与 JOIN 数一致,两侧聚合函数集合不一致);
   - `FILTER` 谓词/时间窗差异(聚合一致,过滤面不一致);
   - `OTHER` 未归因。
3. **统计输出**:全量评估的统计块在既有四组分数之后增列一级分类计数 + SELECT
   的层拆分;失败明细每行带分类名与判据原文(可审计,SHALL NOT 只给结论)。
4. **多轮**:多轮失败轮次以同一纯函数归因(入参足够时),不做跨轮因果追责。
5. **OTHER 桶纪律**:OTHER 必须显式报告数量与题目 id;占比 ≥20% 时评估输出
   SHALL 提示「归因规则不足,需人工扩充」,SHALL NOT 静默接受。
6. **用途边界(硬约束)**:归因结果 SHALL 用作提案立项与知识治理排序的证据面;
   SHALL NOT 作为回归红线——红线仍为黄金指标劣化 ≥5pp 与提示词指纹可比性
   (eval 域基线管理 + 073)。启发式判据敌不过 LLM 采样波动,拿它当闸会误伤。
7. **文档**:归因口径进 `evals/README.md`(与 gold 编写规范同处),新增用例/
   改判据先读它。

## Non-goals

- **LLM 当裁判分类**——不做:不可复现、自己会错、还多花 token;所有判据都是
  确定性计算。
- **归因结果入库/建表**——不做(ADR-004 零触发):评估是进程外工具,归因只进
  评估输出与 nightly 产物的 raw tail(现有 workflow 已收录输出尾部,无需改
  CI 工程)。
- **自动修复闭环**——不做:归因是指向,不是处方;修复动作回到知识/关系/prompt
  的正常变更流程。
- **跨轮因果追责**——不做(见 What Changes 第 4 条)。
- **结构化 summary 改写 eval-nightly 红线脚本**——不做,超出本变更域;真要动
  属 CI 工程,单独立项。
- **按分类设通过率阈值**——不做,见用途边界硬约束。

## Capabilities

### Modified Capabilities

- eval:新增「失败归因分类」Requirement——确定性一级分类(九类)、唯一归类、
  明细带判据原文、SELECT 层拆分、OTHER 桶纪律、多轮复用、用途边界
  (证据面而非红线)。

## Impact

- **落点**:`apps/api/evals/attribution.py`(纯函数)、`evals/test_eval.py`
  (full 集统计块与明细、multiturn 失败轮次调用)、`evals/README.md`(口径文档)、
  `apps/api/tests/test_eval_attribution.py`(纯函数单测,进默认门禁,
  不依赖评估环境)。
- **无 schema 变更**(ADR-004 零触发)、**无契约变更**(ADR-005:评估器是进程外
  工具,不经 OpenAPI)、**信任边界无涉**(ADR-002:不进任何运行时代码路径)。
- **依赖**:与 088 同期落地;088 的收益证据由本归因的 SELECT/JOIN 计数变化 +
  Execution Match 对照提供。两变更任一齐备即可互相读数,无强顺序。
