# 设计:通用工具网关(外部工具域接入框架)

## 范围与证据

- 现状:SQL 域走防火墙 + 六层纵深;knowledge_search(081)单独实现了控制面出站(超时/重试分类/降级观察/审计);021 出站白名单目前只管 LLM 出站(model_allowed_hosts)。
- 本变更是「治理模式推广」,不是新执行语义:所有行为在 081/021/019 里都有单点先例,网关把它们收敛为可复用的域契约。

## D1:域 = 清单 + 策略器 + 执行器,三者分离

- **域清单**(声明式,部署配置文件):域标识、端点、白名单、超时、重试分类、脱敏策略标识、限流配额、审计域标签。清单是数据,装载为纯函数(同配置同结果),畸形单域剔除告警。
- **策略器**(代码,每域一个):出口校验/参数校验/响应脱敏/重试分类四职责,纯函数、零框架依赖(models 层),可脱离容器确定性单测——这是 SQL 防火墙(sqlfw 域包)既有形态的直接复刻。
- **执行器**(代码,每域一个):协议适配(域方言 ↔ 结构化观察),不含治理逻辑。

否决「策略并入执行器」:策略器是安全资产,必须与协议适配解耦才能高频确定性测试(宪法 Article II);否决「策略器配置化(全声明)」:PII 形态与参数约束会持续演进,声明式 DSL 会演化成第二门语言,代码策略器 + 清单数据是复杂度最优解。

## D2:统一出站通道的位置与边界

通道落控制面 `toolgateway/` 域包,形态为一层薄切面:装配鉴权材料 → 策略器出口校验 → 发起出站(超时)→ 策略器响应脱敏 → 审计。它不是新进程、不是新端点——Agent 面仍走既有 `/internal/tool/execute`,回调侧按「工具名 → 域路由」分发:命中域工具走网关,未命中走既有路径(零回归判据)。既有 LLM 出站白名单(021)不动,域白名单是其语义在工具域的平行推广,复用同一配置装载与告警风格。

## D3:迁移策略——knowledge_search 作为锚点

选 knowledge_search 做第一个域迁移而非新增域:它行为契约完整(external-knowledge spec 全场景)、出站治理要素齐全(超时/重试分类/脱敏/审计),是框架覆盖度的天然验收集。迁移判据 = spec 场景逐字段回归 + 评估基线不降。MCP 出站不迁移(Non-goal):mcp-interop 有自己的注册面与写判定语义,强行收编会扩大本变更回归面,留待框架稳定后独立评估。

## D4:审计与限流复用

域执行审计落既有 sys_tool_audit(纯增域标签列或复用元数据字段,取迁移最小面);限流沿用租户+用户固定窗口口径,域配额作为第二维度叠加。不建新表(ADR-004:无新 schema 需求,域状态不落库——启停为部署配置变更,重启生效,与部署级工具注册同语义)。

## D5:测试策略(安全规则类,测试先行)

失败测试先行清单:出口未命中白名单不发出网络请求、缺策略器域不注册、脱敏先于观察、响应类错误不重试、畸形清单单域剔除、停用域零感知。策略器纯函数直测 + 回调链路集成测(内 token 鉴权/审计断言),不依赖真实外部端点(mock 域执行器)。

## 风险与缓解

- 回归面:分发改造触碰既有回调主链——以「未命中域走原路径」为结构判据,六工具 + knowledge 全量回归测试先行。
- 域方言多样性(未来 web 检索 vs HTTP 连接器):执行器接口只约定「结构化观察」出入参,方言细节封在各域执行器内,框架不感知。
- 热加载缺失(Non-goal 声明):启停重启生效,与部署级注册一致;若未来需要热启停,走独立变更。
