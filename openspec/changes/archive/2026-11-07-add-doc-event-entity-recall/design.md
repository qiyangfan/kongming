# Design: add-doc-event-entity-recall

## Context

- 同日 `add-retrieval-quality-eval` 已交付:文档检索试跑端点(逐路可见结构)
  + evals retrieval 层基线。本变更的实体路必须挂进该逐路结构,归因不返工。
- SAG 论文机制(chunk→事件+实体潜在超边;查询时共享实体 join 动态实例化;
  证据始终回原始块)做单库化取舍:Kongming 的父块回填(small-to-big)已
  承担「语义完整单元」角色,实体做词法索引即可,不需要实体向量。
- 摄入现态零 LLM;端口纪律(Protocol+组合根注入,参照 TableDescriberPort/
  RerankPort);kill-switch 先例(rag_expand_enabled、精排「能力从未存在」
  语义);出站统一通道语义(白名单/超时/错误分类)。
- ADR-004:UUID v7 主键、VARCHAR+CHECK、timestamptz、演进走新迁移。

## Goals / Non-Goals

**Goals:**
- 多跳补跳可归因:实体路命中在试跑端点独立可见,off/on 对照进基线表。
- 缺省关、降级无声:未配置 LLM 的部署零行为变化、零成本、零配置痕迹。
- 主检索与引用键派生零回归。

**Non-Goals:** 见 proposal Non-goals(不建图、不三元组、无实体向量、无异步化)。

## Decisions

### D1: 实体粒度 = 父块批量抽取,子块粒度落库

LLM 按父块调用一次,输出该父块内各子块的实体列表,落库行=实体×子块。
备选:按子块抽取(调用数约为 ×4)成本否决;按父块落库(join 后仍需一次
子块映射,无收益)否决。join 粒度与检索候选粒度(子块)一致,融合池并池
不需要二次映射。

### D2: 实体 = 轻量词法索引,不做实体向量

SAG 同口径:实体是索引与扩展点,不是语义载体。表列=name、name_normalized
(规范化 join 键)、name 全文索引(词法兜底用);不占 pgvector 维度,向量
索引仍只覆盖子块。词法兜底=问句词项匹配实体名,保证 LLM 识别不可用时路径
仍可降级运转。

### D3: 查询实体识别 = 端口一次调用 + 词法兜底并集

问句经同一抽取能力面识别实体(一次小调用,部署启用时才发生),与词法兜底
结果取并集作 join keys。备选(仅词法,零 LLM)否决:问句改写形态
(「那个等级的权益」)词法命中率低,多跳主场景恰是这类;备选(仅 LLM)
否决:识别不可用时路径完全失效,违反降级纪律。

### D4: 候选并入配额 + 融合位置

实体路命中子块按「共享实体数」排序截断后并入 RRF 融合候选池(与向量/全文
同池同融合函数);配额部署级可配(缺省小值,防高频词实体把池打爆)。rerank
与父块截断对实体路子块一视同仁——排序质量交给精排,扩展路只负责「补进池」。

### D5: 句界校准独立开关、缺省关(与实体开关正交)

句界校准会改变子块切分,从而改变向量/全文两路的块形态——若与实体路同开关,
①基线对照的归因会混浊(「增益来自补跳还是来自切分质量」)。正交开关使
对照可跑三组:off/off(=①基线)、on/off(实体增益)、on/on(叠加形态)。
缺省关保证未配置部署零回归。

### D6: enrich 端点 = 覆盖式重抽

`POST /system/document/documents/{id}/enrich`:对既有文档先清后抽实体
(与同名覆盖式更新语义一致);不做增量 diff(实体集小,覆盖式简单且幂等)。
免重传文件(上传幂等要求文件内容,既有文档重传不必要)。

### D7: 对照实验口径进 harness

evals retrieval 层 runner 支持实体开关两组运行(部署开关经环境控制,两组
分别跑);README 基线表记录 off/on 两行(标注开关态与题量)。红线判定只在
同开关态内比较,跨态比较只作分析不作红线。

## Risks / Trade-offs

- [上传延迟:开启抽取后上传同步包含 LLM 调用] → 个人项目文档量级小可接受;
  enrich 端点提供「先传后抽」逃生;异步化登记为 Non-goal 另立。
- [高频词实体污染候选池] → 配额截断 + rerank 兜底;抽取 prompt 约束实体
  为专有指称与领域概念,过滤泛词。
- [抽取质量不可控] → 评测红线守护(实体路开启后 Recall@5 劣化即回滚开关);
  prompt 固化不随语料漂移。
- [迁移] → 新表独立,回滚 drop 零数据风险(实体可再生);缺省关时旧文档
  无实体行,不影响任何既有查询。

## Migration Plan

新迁移建伴表(编号顺延);部署顺序无依赖;回滚 = drop 表 + 关开关,
文档与块数据零影响。
