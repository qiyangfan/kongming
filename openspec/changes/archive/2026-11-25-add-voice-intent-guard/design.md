# Design: add-voice-intent-guard

## Context

本变更接在 `add-voice-call` 之后。现状与缺口:

- 模型会话只配置了一个工具 `ask_kongming`;状态机只在**有在途轮**时取消模型的
  擅自回应(`response.created` 分支),空闲期的模型回应不受约束。
- 停止只能靠「新提问顶掉旧轮」:用户说「先不查这个了」但没有产生工具调用时,
  在途轮继续执行;该句也不落库。
- 浏览器收到模型音频增量就解除本地静音;音频是否「该播」完全取决于事件流,
  没有服务端的放行判据。

真机证据(2026-11-25):一次 228 秒通话里,审计轮数与问答工具轮一一对应;用户
要求停止后旧轮未停,直到下一问到达才收敛为已取消;另出现模型未走工具、自行
给出与库内结果不一致数字的发言,落库侧无任何痕迹。

## Goals / Non-Goals

**Goals:**

- 停止意图成为可执行的协议行为:取消在途轮、不发起新问答、给确认。
- 模型在未取得问答结果时没有发言权:服务端放行才播报,未放行即取消。
- 全部行为可用假管道做进程内测试,不依赖真实模型。

**Non-Goals:**

- 不引入通用意图识别或第二套问答链路。
- 不落语音转写、不新增表/列、不改审计字段。
- 不依赖模型服务提供 `tool_choice` 等新协议能力。

## Decisions

### D1 停止用独立工具,不复用提问工具

备选:

| 方案 | 评价 |
| --- | --- |
| 让模型把「停止」也交给 `ask_kongming` | 会生成一条无意义的问答轮并落库;停止语义与提问混在一起,取消时机也不可控 |
| 前端按关键词识别「停止」 | 听写文本不可靠、方言/语气漏判;浏览器不持有在途轮标识 |
| **独立 `stop_current_query` 工具(选)** | 模型负责语义判断,后端只做取消;零参数、无副作用,状态机可测 |

流程:模型调用停止工具 → 后端复用既有取消端口取消在途轮(不执行
`turn.request`)→ 回一个停止工具结果(不触发 `response.create`)→ 浏览器播放
固定停止确认 → 状态回到聆听。无在途轮时为纯确认。

### D2 自答拦截:服务端放行 + 未放行保持静音

只在模型侧写「不要自己回答」不够(实测会被绕过),而在 `response.created` 时
取消又会误伤工具调用。做法分两层:

1. **后端判定**:空闲期(无在途轮、无待放行回应)收到模型的文字/语音回应时,
   发 `response.cancel`;工具调用轮(输出项为 function_call)不取消。取消以
   第一个非工具输出项为触发,漏出的前置语音由第 2 层兜住。
2. **浏览器放行**:远端音频默认静音;只有后端在问答结果回填时发出「放行播报」
   控制消息才允许远端播报。工具调用轮和自答轮都听不到;被取消的回应即使还有
   残余音频增量,也不会解除静音。固定应答与停止确认是本地预录音频,不经过远端
   音频链路,因此不占用远端放行。

放行的状态机只有一种来源:我方 `response.create`(工具结果/失败说明)。固定
应答与停止确认由浏览器本地播放;其余一律不放行。

### D3 停止确认用固定录音

与既有固定应答同形态:一段与模型同音色的预录短句(例如「好的,已停止」),
由浏览器在收到停止确认时播放。理由:零延迟、零 token、不新增一个需要管理的
模型回应;代价是措辞固定——与 D5(等待期固定应答)的取舍一致。录音按当前
默认音色生成,改音色须重录(与既有固定应答同一约束)。

### D4 状态机与通道

- `CallStateMachine` 增加停止工具的分发:参数为空,取消 `pending_trace_id`,
  清空 `pending_token`/`pending_call_id`,不计轮数、不回填;回一个停止工具的
  `function_call_output`(关闭函数调用,不发 `response.create`),并输出一个
  `BrowserSend{type:"turn.stopped"}`(浏览器播放本地确认)。
- 增加放行状态:`_playback_allowed` 仅在发 `response.create`(工具结果)时置位;
  `response.done` 后清除。空闲期/等待期的非工具回应按其输出项类型取消;工具
  调用输出项(ask/stop)不取消,停止工具用独立分发取消在途轮并播本地确认。
- 通道适配层把 `turn.stopped` 与 `playback.allow` 原样下发浏览器;浏览器播放
  闸门以放行为准,不再以「收到音频增量」为准。固定应答与停止确认是本地音频,
  不需要远端放行。

### D5 测试策略

- 状态机:停止工具取消在途轮且不发 `turn.request`;无在途轮只确认;空闲自答
  被取消;工具调用轮不取消;工具结果后的回应放行;停止确认放行。
- 前端纯函数:未放行时音频增量不解除静音;放行后解除;停止确认只播一次。
- 通道集成:停止消息到达浏览器;放行消息先于回答音频;自答轮无放行消息。

## Risks / Trade-offs

- [模型在工具调用前说开场白] → 放行前已静音,用户听不到;工具调用不受影响。
- [模型把「停下,听我说」误判为停止查询] → 指令限定「明确要求停止当前查询」;
  最坏是取消一轮可重问的查询,不影响数据与审计。
- [模型服务不返回可识别的输出项类型] → 以取消 + 默认静音双保险;最坏漏一句
  极短开场白,不会漏出完整数据答案。
- [放行消息与音频事件的先后竞态] → 放行先于 `response.create` 下发,浏览器
  收到即解除;音频事件晚到不影响。
- [停止确认与固定应答同音色资产增多] → 仅多一条短录音,静态资源可忽略。

## Migration Plan

- 无数据库迁移。先部署 api(第二工具、放行与取消判定),再部署 web(默认静音
  与停止确认);顺序反了只是浏览器仍按旧判据播放,不回退数据。
- 回滚:去掉停止工具与放行状态即回到当前行为;无数据处理。

## Open Questions

- 停止确认的措辞与是否与固定应答共用轮换清单(实现期可调)。
- 放行控制消息是否复用语文字通道的现有 `type` 命名空间(实现期定)。
- 空闲自答被取消时是否需要在审计里留一个计数(当前列为非目标,待真实运维
  需要再评估)。
