# Proposal: add-voice-intent-guard(语音意图护栏)

## Why

真机通话暴露两处与「语音模型只当耳朵和嘴」相冲突的行为:

- **没有停止意图。** 用户说「先不查这个了」时,系统没有把它识别为停止:只有
  下一条提问产生工具调用后,旧轮才会被取消。等待中的查询会继续跑完,用户听到
  的是一段与当下意图无关的结果;该句本身也不落库,事后无法解释为什么查询没停。
- **模型可以自答。** 现有保护只覆盖「等待期模型擅自开口」;通话空闲时,模型
  可以凭自己的知识直接回答数据问题。实测出现过与库内结果不一致的数字:这类
  发言不经过问答链路,不落库、不进审计,用户与事后排查都分不清它是不是查询
  结果。竞品里这叫「语音模型在替大脑说话」,在孔明等于绕开 SQL 防火墙、租户
  数据范围与审计。

两处都指向同一个缺口:语音层缺少对「用户意图」和「模型发言权」的硬约束,只靠
行为说明与提示词。本变更把两条约束做成可测试的协议行为。

## What Changes

- **停止意图**:模型会话固定工具扩为两个——「把问题交给助手」与「停止当前
  查询」。用户明确要求停止时,模型调用停止工具;后端取消在途问答轮(与用户
  显式取消同语义),不发起新问答、不回填结果,播放一句固定的停止确认。该句
  不作为问答消息落库;无在途轮时只确认、不产生问答副作用。
- **自答拦截**:除系统固定应答、停止确认与问答结果播报外,模型在未取得问答
  结果时的自有发言一律不放行。系统在未放行状态下保持远端静音,并对空闲期的
  文字/语音回应发取消;工具调用轮保持静音,工具结果返回后的播报才放行。
  未放行的发言不落库、不进审计正文。
- **确认音**:停止确认沿用固定应答的形态(与模型同一音色的预录短句),零延迟、
  零 token,不引入新的模型回应。
- **测试与契约**:状态机的停止、自答拦截与放行各配回归用例;前端播放闸门按
  「未许可即静音」补纯函数测试。WebSocket 文字通道新增停止确认与放行两种控制
  消息,不涉及 OpenAPI。

## Capabilities

### Modified Capabilities

- `voice-call`:MODIFIED「通话建立与模型会话配置」(工具清单由固定一个改为固定
  两个);ADDED「停止当前查询」与「语音回答必须来自问答链路」。既有「新提问
  取消上一轮」「结果回填与补交」「等待期固定应答与擅自回应掐断」保持不变,
  本变更只在它们之上增加停止工具与放行闸门。

## Impact

- **信任边界(ADR-002 / ADR-013)**:语音模型仍然只当耳朵和嘴。新增的放行闸门
  把「模型能不能说」从提示词约束提升为服务端约束;浏览器不再以收到音频事件就
  解除静音,改为以系统放行为准。模型服务密钥与音频路径不变。
- **契约管线(ADR-005)**:浏览器与 api 的文字通道新增一种控制消息(放行播报);
  OpenAPI 与生成类型不变,`make contracts` 无增量。
- **schema(ADR-004)**:无新表、无新列、无迁移。停止沿用既有取消终态;自答拦截
  的发言不落库。通话审计字段不变。
- **代码落点**:`apps/api` 的 voice 状态机与通道适配层(第二工具、放行状态、
  空闲回应取消);`apps/web` 通话搬运层(未放行保持静音)与一条停止确认录音。
  问答域的取消端口复用,零改动。
- **已知限制**:模型若在工具调用前先说一句开场白,该句在放行前已被静音,用户
  听不到但工具调用不受影响;被取消的自答不报告用量,审计口径不变。

## Non-goals

- **不落语音转写**:停止句与自答内容都不进会话历史;只保留被取消轮的已取消说明。
- **不做通用意图框架**:只增加停止一个工具,不开放多工具编排或写操作。
- **不改问答链路**:取消仍复用既有的在途轮取消与已取消终态,不新增取消语义。
- **不改审计字段**:不增加停止次数、拦截次数等新列;需要时另行提案。
- **不改固定应答的音色与措辞**:停止确认沿用同一音色(与本次实现修复一致)。
- **不做模型侧强保证**:不依赖提供方支持 tool_choice 等新参数;放行与取消由
  本仓服务端完成。
