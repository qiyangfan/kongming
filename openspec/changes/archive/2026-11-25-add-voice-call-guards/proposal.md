# Proposal: add-voice-call-guards(语音通话滥用防护)

## Why

语音通话(ADR-013)把声音直连给浏览器,后端只做牵线与文字事件控制。凭证与媒体面
的取舍是正确的,但复盘发现一个结构性缺口:**后端无法终止已经建立的模型会话,
收口依赖浏览器配合。** 改过的客户端可以忽略结束通知继续与模型对话;文字通道断开
后后端释放准入,浏览器仍可保留媒体连接。于是「一人一通 + 并发 2 + 单次 10 分钟」
的封顶只对诚实客户端成立,恶意客户端可以叠加「僵尸会话」,费用记在部署的模型账号上。

上游硬边界(2026-11-25 查百炼官方文档):

- 单次会话最长 **120 分钟**,达到上限服务端主动关闭;文档里的 600 秒是上下文
  音频保留时长,不是会话持续时间。
- 千问 Omni-Realtime 按账号限流:`qwen3.8-omni-flash-realtime` 建连 RPM 60、
  TPM 200 万;限流文档在 WebSocket 一节说明「未单独限制同时保持的连接总数」,
  WebRTC 未单列并发上限。
- 客户端事件清单里没有 `session.close`;WebRTC 结束会话只能由客户端停止媒体并
  关闭 PeerConnection,没有服务端关闭接口。
- 临时 API Key 可下发,但 TTL 1–1800 秒、继承父 Key 全部权限、不能提前删除,
  不适合替代现在的服务端牵线。

因此需要在服务端加不依赖客户端自觉的闸:建连频次与 24 小时建联预算。顺带修三处
小口子:通话审计的租户没有做白名单校验;通道票据走 URL query,已确认会进
uvicorn 访问日志;审计里的轮数与音频用量由浏览器转发的事件得出,不能当计费依据。

生态对照也支持这个分层:OpenAI 对浏览器/移动端推荐 WebRTC、服务端到服务端用
WebSocket;阿里把 WebSocket 定位为服务端集成与原型、WebRTC 定位为浏览器实时
音视频;LiveKit 前端↔Agent 用 WebRTC、Agent↔后端用 WebSocket。WS 的优势场景
是服务端持有媒体、电话链路与受限网络,不是浏览器直连的低时延音频。参考实现
`ai-chatbot` 同样是后端代换 SDP、浏览器持 WebRTC,且它的本地会话时长也明确
不代表供应商强制断连。

## What Changes

- **建连频次闸**:同一用户每分钟的建联请求次数有上限;超限以限流语义拒绝,
  不占用通话准入,不向模型服务发起交换。
- **24 小时建联预算**:同一用户与整个部署各自有成功建联次数上限;额度原子占用,
  建立失败释放;超限拒绝。默认值见 design,全部可配置,0=不启用。
- **通话租户归属**:建立通话时校验声明的租户属于本人且启用;未声明取默认租户;
  无法确定有效租户即拒绝。审计记录校验后的租户。
- **票据移出 URL**:通道票据改由 WebSocket 子协议传递(访问日志只记路径);
  保留一版 query 兼容,老前端不受部署顺序影响。
- **审计口径**:明确轮数、打断次数、音频用量是浏览器转发事件的参考值,不作
  计费依据;日预算拒绝落一条 `chat.voice.call_rejected` 审计,便于观察滥用。
- **WebSocket 帧上限**:api 镜像的 uvicorn 加 `--ws-max-size`,应用层对单帧再做
  一次上限检查并关闭超限连接。
- **决策与文档**:新增 ADR-014 记录「上游收口边界 + 服务端预算闸」的取舍;
  ADR-013 加指向说明;`docs/tech-stack.md`、`docs/HANDOFF.md`、`.env.example`
  同步新配置与已知边界。

## Capabilities

### Modified Capabilities

- `voice-call`:新增「通话滥用防护」与「通话租户归属」两条行为要求;既有要求不变。

## Impact

- **信任边界(ADR-002 / ADR-013 / 新增 ADR-014)**:不改变「模型密钥只在 api、
  媒体不经过后端」的构造;新增的是服务端自保闸,吸收「客户端可保留会话」这一
  已知弱点。agent 面零改动。
- **schema(ADR-004)**:无新表、无新列、无迁移。预算计数在 Redis。
- **契约(ADR-005)**:无新端点、无新字段;新增的 429 只走运行时错误体;
  `make contracts` 应零差异。
- **部署**:新增三个可选环境变量(`KM_VOICE_ESTABLISH_RATE_PER_MINUTE`、
  `KM_VOICE_DAILY_CALLS_PER_USER`、`KM_VOICE_DAILY_CALLS_PER_DEPLOYMENT`),
  缺省即生效、0=关闭;api 先上(同时接受两种票据传输),web 后上;回滚只需把
  三个值配 0。api 镜像的 uvicorn 增加 WebSocket 帧上限参数。
- **代码落点**:`apps/api` 的 voice 域(ports/repository/service/router/errors)
  与组合根;`apps/web` 的失败分类、通道建连与文案;两侧测试。
- **已知限制**:上游 120 分钟硬上限决定了最坏暴露时长;预算按「成功建联次数」
  近似,不按 token 精确计费;客户端上报的审计计数仍是参考值;开放注册场景下
  多账号轮换不在本变更范围。

## Non-goals

- **不把媒体改回后端转发**:不部署 TURN/SFU,不改 ADR-013 的声音直连。
- **不下发临时 API Key**:权限继承太宽且无法提前失效,不引入第二套凭证形态。
- **不追求对恶意客户端的强制收口**:心跳、人机校验、客户端证明都可伪造,上游
  也没有关闭接口;只做服务端预算闸与文档边界。
- **不做通话表、通话统计页或按 token 的账单对账**。
- **不做租户/IP 维度的差异化配额**:只做用户与部署两维,避免共享出口误伤。
- **不承诺跨厂商同一浏览器传输**:语音只接阿里一家;Gemini Live 官方是 WSS +
  短期 token、没有原生 WebRTC 直连,若接入需另立 provider adapter(浏览器 WS
  或服务端桥接),也不允许只改 base URL/model 接入。
- **不为假设的供应商预建适配层**:不提前实现第二家;只把「浏览器传输/凭证模式」
  写成接入前必须登记的 profile 与检查清单。
- **不改模型、断句、问答链路、固定应答与播放闸门。**
- **不引入新的观测系统**:告警用百炼控制台现有的费用/用量告警,代码只落审计
  与日志。
- **不解决开放注册下的多账号轮换**:账号准入与注册风控是另一条防线,不在本变更。
