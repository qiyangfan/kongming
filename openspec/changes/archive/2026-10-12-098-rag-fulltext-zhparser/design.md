# Design

## Context

- tsv 全文向量为应用层维护(`rag` 域 repository.py 与 documents_repo.py 共
  5 处 SQL 内联 `'simple'` 字面量:写入 2 处、检索 3 处);列形态为普通
  tsvector 列,无配置元数据。
- 全文路判据消费方:064 召回闸门(全文路原生分=ts_rank,阈值量纲已按
  0.28 标定)。分词配置变更会改变 ts_rank 量纲——这是「配置变更必须走
  重算 + 阈值复标定」的根因,须在文档明示。
- 检索上下文缓存(Redis)键当前不含分词配置维度。

## Goals / Non-Goals

**Goals:**

- 配置单源:一处读取、白名单校验、写读同配置。
- 零回归:缺省 simple 时全部 SQL 形态与现值逐字一致。
- 生效路径明确:配置变更 → 重启自检 → 重扫/重建重算 → 缓存隔离。

**Non-Goals:**

- 不做逐租户/逐数据源分词配置(部署级单值足够,个人项目无混部需求)。
- 不引入 Python 侧中文分词依赖(jieba 应用层方案,见 Decisions 对比)。
- 不改 064 闸门结构(阈值复标定走既有配置,非本变更范围)。
- 不自动检测配置漂移(存量 tsv 与当前配置不一致的检测不做——重算是
  显式运维动作,文档写清配方)。

## Decisions

1. **zhparser 而非应用层分词(jieba)**:zhparser 是 PG 原生扩展,写入与
   查询侧 SQL 内一致,无文本预处理管道;应用层分词需在 embedding 文本与
   检索文本之间维护「分词后拼接」的第二形态,派生检索文本与原文脱钩的
   风险(095 alias 教训同形)不值得。roadmap 待办亦点名 zhparser。
   代价:部署环境需装扩展(pg18 localenv 配方进文档)。
2. **白名单枚举而非任意 ts_config 名**:配置名是标识符,无法绑定参数,
   内联进 SQL 前必须白名单(`simple`/`zhparser`);开放任意名是 SQL 注入面
   与拼错静默失效的双风险。新分词器 = 白名单加一项 + 文档,可接受。
3. **不可用一律拒启(prod/dev 同)**:检索配置降级不安全(与 websearch
   「降级=域不注册」不同形——这里降级=换词法,存量 tsv 直接错配),故
   不照抄 websearch 的 dev 告警降级。启动时查 pg_ts_config 自检。
4. **缓存隔离方式**:检索上下文缓存键纳入分词配置值(键版本化最简形态),
   不做「切换时主动清缓存」(部署级配置只在启动读,键含配置即天然隔离)。
5. **SQL 参数化形态**:配置名经白名单校验后仍内联(标识符无法参数化),
   但收敛到单一常量来源(配置单点格式化),杜绝第二处字面量。

## Risks / Trade-offs

- [zhparser 分词改变 ts_rank 量纲,064 全文路阈值需复标定] → 文档明示:
  切配置后须重扫 + 影子期复标全文路阈值(recall-probe 试跑面支撑);缺省
  simple 不受影响。
- [扩展安装失败阻塞启动] → 自检文案明示缺项与安装配方指引;simple 缺省
  不装扩展的部署零感知。
- [documents_repo 与 repository 双处内联遗漏] → 全仓 grep `'simple'` 清零
  断言进测试(除配置单点外不得出现字面量)。

## Migration Plan

1. 合入后缺省 simple,零行为变化;2. 需要中文分词的部署:装 zhparser 扩展 →
   配置切换 → 重启(自检过)→ 逐数据源重扫/重建(既有 fetch-metadata/
   reindex/上传链路)→ 影子期复标全文阈值 → 切 primary。
   回退:配置改回 simple + 重建,或直接 revert(零 schema 依赖)。
