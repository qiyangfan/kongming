# Design: add-voice-call

## Context

动机与范围见 proposal.md。与本设计直接相关的现状与约束:

- **已有的语音能力**只有语音转写(`/chat/stt`,可选启用形态);web 没有任何
  实时音频、点对点连接或 WebSocket 代码,api 没有任何 WebSocket 端点。
- **登录只认 `Authorization` 请求头**。浏览器的 WebSocket 无法携带自定义
  请求头;cookie 里只有 HttpOnly 的刷新令牌与 OAuth state,都不能当作现成的
  凭据。问答端点的租户取自 `X-Tenant-Id` 请求头。
- **流式问答**:浏览器 `POST /chat/query/stream`(SSE),`ChatService.start_stream`
  返回「帧队列 + 后台任务」的句柄。前置变更 `add-chat-turn-cancel` 会引入
  在途轮登记、用户取消与已取消终态;本变更复用它。
- **问答配额按 `sys_llm_usage` 的行数计**,不区分任务类型。
- **操作审计**已有:`SqlOperLogRepo.add(user, action, target, detail)` 与
  `/audit/oper/page`(按动作、用户、时间筛选,按数据范围收敛可见性)。
- **出站 HTTP 用 httpx**。api 的测试栈是 httpx + ASGITransport,没有现成的
  WebSocket 测试客户端;测试环境禁止非回环网络,出站调用必须替身。
- **单节点部署形态**;领域代码零框架依赖,外部能力经 Protocol 反转。

**实测依据**(2026-11-24,阿里 `qwen3.8-omni-flash-realtime`,13 次后端直连 +
1 次浏览器直连,共约 0.02 元):

| 实测事实 | 对设计的含义 |
| --- | --- |
| 普通断句(server_vad)下,等待期间用户「嗯」一声会触发新回应,模型随即编造答案,原查询调用编号作废 | 断句必须用按语义的方式(D4);后端必须能掐断擅自回应、能补交结果(D3) |
| 按语义断句(semantic_vad)下,同一声「嗯」被过滤,原结果正常交回 | 附和不需要特殊处理 |
| 模型提出工具调用的那一轮完全不出声 | 等待期需要一句固定应答(D5) |
| 看到「模型要说话」的事件就发取消,漏出声音 0 秒 | 掐断以事件为触发,不以声音为触发 |
| 调用编号作废后,把答案作为文字消息补交,模型照念且数字一致 | 补交走文字消息,不依赖原调用 |
| 干等 12 秒、30 秒:不断线、零报错 | 孔明一轮 8–11 秒的时延在会话层可接受 |
| 念出的数字 7 次全对,措辞偶有轻度改写 | 回答以页面为准,语音只负责念 |
| 被取消的回应不报告用量;静音不计音频 token | 用量只能如实记,值偏低 |
| 按语义断句判定插话较慢(语音时长 + 判定约 3 秒) | 即时打断感要靠浏览器本地静音(D6) |
| 浏览器 0.04 秒直连成功,无中转 | 声音直连可行;无需部署任何媒体基础设施 |

## Goals / Non-Goals

**Goals:**

- 语音问的每一轮,与打字问走同一个端点、同一套编排——权限、租户、配额、
  防火墙、落库、评分全部复用,没有第二套问答入口。
- 声音不经过孔明服务器;对话的每一步决策与每一次记录都在后端。
- 浏览器只做三件事:传声音、原样搬运文字事件、按后端指示发起问答。
- 通话状态机的全部逻辑放在不依赖框架的纯异步类里,用假管道做进程内测试。

**Non-Goals:**

- 不保证受限网络(禁 UDP)下可用,不部署中转服务器。
- 不追求浏览器恶意篡改下的强 enforcement:信任模型与打字提问同级,靠准入与
  上限封顶(见 proposal 的信任边界表述)。
- 不让固定应答随语境变化。

## Decisions

### D1 声音直连、控制回后端

| 方案 | 做法 | 评价 |
| --- | --- | --- |
| 后端转发媒体 | 浏览器把声音送给孔明,孔明转给模型服务 | 每路通话服务器进出约 0.85 Mbps(未压缩声音,16/24kHz);Python 控制面进程要为每路每秒搬几十个声音块;多一到两跳时延,抖动与回声处理要自己写。OpenAI、谷歌、阿里的官方做法都是浏览器直连 |
| 浏览器编排(小助手做法) | 后端只牵线,之后模型与浏览器之间的事后端看不到 | 后端无法知道模型是否擅自作答,无法掐断;记录靠浏览器上报 |
| **声音直连 + 控制回后端(选)** | 浏览器与模型服务直连声音;浏览器与后端之间一条只传文字事件的通道,决策全在后端 | 服务器不搬声音;每一步可见、可控、可测。与 OpenAI「server-side controls」同构,阿里没有原生旁路通道,由浏览器代为搬运文字事件 |

### D2 提问仍走既有流式问答端点,由浏览器发起并带关联字段

备选是「后端代起一轮」:通话状态机直接调 `ChatService.start_stream`,再把
过程帧推给浏览器渲染。不选,三个原因:

- **同一个端点才是「同一条链路」的字面意思。** 浏览器发起,权限头、租户头、
  配额检查、请求校验、过程卡的渲染路径全部是现成的,一行不改。
- **租户在请求头里。** 浏览器的 WebSocket 带不了 `X-Tenant-Id`;后端代起一轮
  就得另外把租户带过去,多一条要维护的隐式约定。
- **过程帧要多一条来源。** 渲染层目前只认 SSE 一种帧源;后端代起就得再加一套
  「从通道来的帧」,改动面更大。

选定的接线方式(依赖方向:通话域 → 问答域;问答域只认一个 Protocol):

1. 通话侧收到模型的工具调用 → 若已有在途轮,先取消它 → 签发一次性的
   `voice_turn_token` → 经通道下发 `turn.request{token, question=听写原话}`。
2. 浏览器收到后播放固定应答,并以「听写原话 + token」调用既有的
   `/chat/query/stream`。
3. 问答侧在落用户消息**之前**校验 token(存在、属于本人、未使用),发起在途轮
   后调用绑定端口 `bind(token, 在途轮句柄)`。
4. 通话侧等待绑定(5 秒),再等待终态,拿到 `ChatOutcome` 后回填。

问题文本用听写原话而不是模型的参数:实测模型有时会把「换成上周的」改写成
完整问题,有时原样传。孔明自己有多轮指代消解,输入与打字保持一致最稳。

### D3 协议由后端驱动,浏览器只搬运

浏览器把模型会话的每个事件原样转给后端;发给模型的内容只有后端指示的。
后端的通话状态机维护一张小表:

| 看到什么 | 后端做什么 |
| --- | --- |
| 工具调用 `ask_kongming`(新一轮) | 有在途轮则取消它;签发 token;下发 `turn.request` |
| 在途轮进行中,模型自行开始一个回应 | 立即发 `response.cancel`;标记「原调用已失效」;在途轮继续 |
| 在途轮结束,原调用仍有效 | 发工具结果 + `response.create` |
| 在途轮结束,原调用已失效 | 把结果作为文字消息补交 + `response.create` |
| 在途轮失败 | 回填「没有查到」,让模型如实说明 |
| 在途轮被取消 | 不回填 |
| 到时长上限 / 通道断开 | 取消在途轮,结束通话 |

「模型自行开始的回应」怎么认:后端每次主动发 `response.create` 时挂一个
「等待一个由我发起的回应」的标记,下一个「回应开始」事件算作自己人;没有
标记时收到的「回应开始」都是擅自回应。窗口极小(两条消息交错的一瞬间),
最坏情况是多念一句,可接受。

交给模型念的文本 = 回答摘要;有结果表或图表时末尾附「详细数据已经显示在
屏幕上」;出现待确认的写操作时说明「这个操作需要在页面上确认」。

### D4 断句用按语义的方式

实测对照见上表。按语义断句是模型的会话配置项,由后端固定生成。

### D5 等待期用固定应答录音

| 方案 | 评价 |
| --- | --- |
| 不出声 | 提问后 8–11 秒完全安静,像断线了 |
| 让模型说一句「我查一下」 | 要多一次模型回应,约 1 秒后才出声,还多一个需要管的回应 |
| **固定录音(选)** | 零延迟、零 token、没有新的状态要管;代价是措辞固定 |

录音用同系列的合成语音生成一次,作为静态资源入库(两三句轮换)。

### D6 打断:浏览器本地静音,服务端负责取消

- 浏览器一收到「检测到说话开始」就静音远端声音——不等后端判定出新问题
  (实测按语义断句的判定要两三秒)。
- 后端收到同一事件后取消旧回应;新的工具调用到达时取消在途轮(D3)。
- 不在浏览器里另做本地人声检测:先用模型服务侧的说话开始事件(实测比人开口
  晚零点几秒),不够再评估。

### D7 通话记录走操作审计

| 方案 | 评价 |
| --- | --- |
| 新建通话表 | 只有存在「通话记录页」这类产品面时才值;本变更没有 |
| 把实时语音的用量写进 `sys_llm_usage` | 问答配额按该表的行数计且不分类型,写进去会悄悄吃掉用户的问答配额 |
| **操作审计一行(选)** | 复用 `chat.voice.call_end` 动作;现成的审计页就能按动作、用户、时间查;零 schema 变更 |

内容:用户、租户、起止时间、时长、结束原因、提问轮数、打断次数、模型报告的
音频 token(听入/念出)、模型名。不含语音内容、不含密钥。

### D8 文字通道用一次性票据鉴权

登录只认请求头,浏览器 WebSocket 带不了。做法与登录里的 OAuth state 同款:
`POST` 建交通话(带 JWT)时生成 `secrets.token_urlsafe(32)`,存 Redis、60 秒
过期、取出即删;浏览器凭它连 WebSocket;票据绑定用户与通话,非本人或重复
使用直接关闭。租户在建交通话时随请求头一并记入通话状态。

### D9 准入

- 同一用户至多一通:`SET NX EX`,过期时间取「时长上限 + 余量」。
- 并发上限:原子「未满则加一」,结束时减一;计数器带兜底过期,防进程异常
  退出后永久占用。
- **准入对 Redis 故障 fail-closed**(读不到就拒绝建立):它是保护服务器的闸,
  与限流器的 fail-open 语义相反是有意的。
- 时长上限由通话状态机的定时器执行:到点下发结束通知并关闭通道。

### D10 牵线出站的加固

连接请求上限 128KB 且须以 `v=0` 开头;应答上限 256KB 且须以 `v=0` 开头;
不跟随重定向;15 秒超时;失败不自动重试;应答与请求都不写日志(含本机网络
信息);上游错误不透传原文,只返回统一失败并记日志。接入地址来自部署配置,
不是用户输入。

### D11 域分层

`apps/api/kongming/voice/`:router(HTTP 端点与 WebSocket 适配层,薄)→
service(准入、通话状态机:纯 asyncio)→ models(数据类)→ ports(牵线、准入、
票据、审计、在途轮绑定;`typing.Protocol`)→ repository 与基础设施实现(httpx
牵线、Redis 准入与票据)。问答域 `chat/ports.py` 增一个在途轮绑定的 Protocol,
组合根把通话域的实现接进去。WebSocket 适配层只做「收消息 → 交给状态机 →
把状态机的输出发回去」,这样状态机可以完全不碰 WebSocket 做测试。

不直接依赖 `websockets` 库:WebSocket 端点走的是框架自带的接口,不需要新增
依赖声明。

### D12 决策记录与部署上限文档

新增 ADR-013 记下 D1 与信任边界表述;`docs/tech-stack.md` 增一张语音通话
部署级上限表(并发路数、单次时长),沿用现有上限表的格式。

## Risks / Trade-offs

- [受限网络禁 UDP 时浏览器直连失败] → 建立失败时明确提示「当前网络不支持
  通话」;不部署中转(非目标);写进 HANDOFF。
- [浏览器可篡改转发内容或改写会话配置] → 信任与打字提问同级;并发与时长
  上限封顶;按量计费下白用的代价极低(实测一通约 0.003 元)。
- [擅自回应的辨认靠先后顺序] → 交错窗口极小;最坏多念一句。
- [被取消的回应不报用量] → 审计如实记,值偏低;不据此做计费。
- [单节点前提] → 在途通话登记在进程内;多实例部署是既有限制,届时与在途轮
  登记一并外置。
- [api 重启丢在途通话] → 浏览器察觉通道断开即挂断并提示;通话期间的问答已
  落库,不丢。
- [麦克风权限被拒、自动播放被拦] → 通话必须由点击手势发起;被拒时给出明确
  提示,不进入「看起来在通话」的状态。
- [阿里接入地址或模型名变更] → 地址与模型名可配置;HANDOFF 记现值与已失效
  的旧路径。
- [WebSocket 上的审计没有来源 IP] → 现有的来源 IP 中间件只处理 HTTP,扩展到
  WebSocket 范围。
- [路由鉴权守卫不检查 WebSocket 路由] → 为票据鉴权单独写测试,不依赖该守卫。
- [开发代理不转发 WebSocket] → 本地开发代理开启转发。

## Migration Plan

- 无数据库迁移。未配置模型服务密钥时功能不出现。
- 顺序:先归档并部署 `add-chat-turn-cancel`,再部署本变更的 api,最后是 web
  (前端发现建交通话返回 503 即不显示入口,顺序错了也只是入口不出现)。
- 回滚:去掉密钥配置即关闭;没有需要处理的数据。

## Open Questions

- 固定应答的措辞与条数(拟两句轮换),实现期可调。
- 并发上限与时长上限的缺省值(拟 2 路、600 秒),部署常量。
