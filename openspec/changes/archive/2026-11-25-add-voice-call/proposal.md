# Proposal: add-voice-call(语音通话)

## Why

孔明的语音能力目前只有「说一段 → 转成文字 → 填进输入框 → 点发送」。用户不能像
打电话那样连续对话:听不到回答、不能随时打断、每一问都要回输入框确认。这是
输入输出方式上的真实缺口,也是通用智能体方向(ADR-010)在交互形态上的空位。

对照 FoxESS 小助手的实现与大厂官方做法、并对阿里实时语音模型做了真实通话实测
之后,三条结论决定了这个功能该怎么做:

- **不能让语音模型自己作答。** 小助手的语音通道由实时模型直接回答,打字问答
  的主流程不参与。放到孔明,那等于绕开 SQL 防火墙、租户数据范围、配额与审计
  ——恰好是孔明的立身之本。正确形态是「语音模型只当耳朵和嘴,大脑仍是孔明」:
  每一轮语音提问都走与打字提问同一条问答链路。
- **声音直连,控制回后端。** 声音从浏览器直连模型服务,不经过孔明服务器
  (后端转发声音每路约 0.85 Mbps,且音质、时延都更差,大厂一致不这么做);对话的
  每一步决策、每一次记录都留在后端。
- **实测可行,并暴露了两处必须由后端处理的行为。** 听写准确、每问都交给
  孔明、等结果 12–30 秒连接稳定、念出的数字与答案一致、浏览器 0.04 秒直连
  成功;但①等结果时用户「嗯」一声,普通断句方式下模型会编造答案;②模型提出
  查询的那一轮完全不出声。两者在实测中都有验证过的处理办法(见 design)。

**前置依赖**:语音打断要求「说停就真停」,以 `add-chat-turn-cancel` 为前置;
该变更未归档前本变更不开工。

## What Changes

- **通话入口与准入**:对话页加通话入口(复用权限点 `chat:execute`);未配置
  实时语音模型时入口不出现(可选启用形态,同语音转写)。同一用户同时至多一通
  在途通话;并发通话数与单次时长有部署级上限。
- **通话建立(牵线)**:后端代浏览器与模型服务交换实时连接信息并原样返回
  应答,模型密钥不出后端;模型会话的行为说明与工具清单由后端固定生成,工具
  只有「把问题交给孔明」一个;断句采用能过滤附和声的方式。
- **文字事件通道**:浏览器与后端之间新增一条只传文字事件的通道(一次性
  票据鉴权)。浏览器把模型会话的事件原样转给后端,发给模型的内容只限后端
  指示的。音频不经过后端。
- **语音触发问答**:一句话听写完成后,以**听写原话**为问题,走与打字提问
  相同的流式问答端点发起一轮;后端通过请求里新增的可选「语音轮关联字段」
  绑定这一轮,并在它结束时把回答文本交回模型念出。新一轮提问取消上一轮。
- **两道服务端保护**:①模型在等待期间擅自开口,后端立即取消该回应(实测
  漏出 0 秒);②原查询调用失效后,以文字消息补交结果(实测照念、数字一致)。
- **固定应答**:问题交办后立即播放一句预先备好的固定应答(如「我查一下,
  请稍等」),补上模型不出声的那一轮。
- **打断**:用户开口即停止播放并取消旧回应;新的一句话按新提问处理。
- **通话记录**:每通通话落一条操作审计(用户、租户、时长、结束原因、轮数、
  打断次数、模型报告的音频用量)。不建新表。
- **决策记录**:新增 ADR-013,记下「声音直连、控制回后端、语音模型只当耳嘴」
  的取舍与信任边界表述。

## Capabilities

### New Capabilities

- `voice-call`:通话的准入与建立、文字事件通道的职责划分、语音触发问答、
  新问取消旧轮、结果回填与补交、等待期的固定应答与擅自回应的掐断、打断、
  通话记录与结束。

### Modified Capabilities

- `chat`:MODIFIED「问答查询端点鉴权与请求字段」(流式问答请求纯增可选的
  语音轮关联字段,打字提问不携带、行为不变)。
- `query-streaming`:ADDED「系统发起的取消」(后端可在服务端直接取消一轮
  在途问答,语义与用户显式取消一致——语音新问取消旧轮、挂断取消在途轮都用它)。

## Impact

- **信任边界(ADR-002)**:新增一条「浏览器 ↔ 模型服务」的直连通道。模型
  服务密钥只存在于 api;浏览器拿到的只有一次性通道票据与连接应答。信任
  模型与打字提问同级——后端相信登录用户提交的内容,不相信其转发之外的事;
  准入、时长上限与并发上限把暴露面封顶。agent 面零改动,零凭证形态不变。
- **schema(ADR-004)**:无新表、无新列、无迁移。通话记录走既有操作审计;
  语音轮的消息就是普通问答消息。
- **契约管线(ADR-005)**:新增通话建立、挂断端点与一条 WebSocket;流式问答
  请求纯增一个可选字段;`make contracts` 再生并提交产物。
- **部署**:api 新增一组配置(模型服务密钥、接入地址、并发与时长上限),
  缺省不配置即不启用。api 首次出现 WebSocket 端点——当前无反向代理,直连
  即可;日后引入反向代理须透传连接升级。无新依赖。
- **代码落点**:`apps/api` 新增 `voice` 域(router / service / models / ports /
  repository 与基础设施实现),chat 域加一个很小的「在途轮绑定」端口并在
  组合根接线;`apps/web` 新增通话 hook、搬运层、通话状态条,以及两条固定
  应答录音。
- **已知限制**(实测所得,写入 HANDOFF):被取消的回应不报告用量;公司或
  手机等受限网络下浏览器直连未验证(不部署中转服务器);回声消除依赖浏览器。

## Non-goals

- **不让语音模型自己答题**:包括问候与闲聊在内,每一句都走孔明的问答链路。
- **后端不转发音频**:不引入媒体服务器或中转,不为此新增进程或依赖。
- **视频通话、声音克隆、真电话拨入(SIP)**。
- **语音触发写操作**:通话期间只做查询类问答;写工具的确认交互不进通话
  (出现待确认调用时提示到页面上处理)。
- **等待时念进度**:等待期只有一句固定应答与页面上的进度卡;逐段念进度
  等真实体验反馈后再评估。
- **通话记录的管理页与统计**:只落操作审计;通话时长排行、按用户统计等
  观测面不在本变更。
- **语音轮的来源标记**:不给问答消息加「语音发起」列;需要按来源分析
  问答质量时另行提案。
- **实时语音 token 进用量看板**:用量只记在通话审计里,不写用量表(避免
  与按调用次数计的问答配额互相干扰)。
- **多厂商可切换的抽象**:只接阿里一家;端口按本仓惯例留接口反转,不预建
  第二家的实现。
- **即时回声与弱网优化**:不引入回声消除库、抖动缓冲或 TURN 中转。
