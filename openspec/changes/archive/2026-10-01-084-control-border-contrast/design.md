# 084 设计：为什么改 `--input` 而不是改 `--border`

## D1 语义分离早已存在，只是被赋成了同一个值

shadcn 的 token 设计里 `--border`（分隔线/描边）与 `--input`（表单控件边界）本就是两个槽位，
本仓 `index.css` 写成 `--input: #dfe3de;` 与 `--border` 同值——槽位还在，语义被抹平了。
所以修法是**给已有槽位填正确的值**，不是新增设计层。

- **否决：新增 `--control-border`**：同一件事两个 token，必然分叉，且要改所有控件类名。
- **否决：把 `--border` 整体提到 3:1**：`--border` 的消费方是卡片、表格线、sheet 边、底部导航——
  那是「宣纸白 + 青灰线」的品牌基线，拉黑等于把每个容器都套上灰框，属用错药。

## D2 判据取「控件边界 vs 其所在面」，不是 vs 页面背景

控件多落在白卡或弹层上，所以按**最近的不透明祖先面**取值（实测即白卡 3.49、弹层 3.35），
同时保证对页面底也 ≥3:1。参考线取 WCAG 1.4.11 非文本对比 3:1，留 0.3 以上余量，
避免组件叠加半透明填充（如 `dark:bg-input/30`）后跌破。

## D3 各仓按各自色板算值，不跨仓抄数字

kongming 与 jinguan 同调色板（宣纸白/黛墨夜）→ 同值 `#808c86` / `#62767c`；
muniu 是松烟系（`#f7f7f5` / `#131512`，边框色相偏绿）→ 独立算得 `#7c8781` / `#6b7a6f`。
`index.css` 不在 `sync-frontend-standard.sh` 的同步集内（脚本只搬 `ui/*.tsx` 与共享件），
跨仓一致性靠**宪法 Article 3 的口径**（两 token 不得同值 + ≥3:1 + 改色板须重算）而非拷数字。

## D4 色相不漂移

新值都在原色相轴上（青灰 / 黛青 / 松绿灰），只调明度，不改色相与饱和倾向——
观感上是「控件终于有边」，不是「换了一套灰」。亮暗两态各截图复核，无布局位移（只改线色）。

## D5 聚焦环（`--ring` 鎏金）本批不动，但记为已知弱项

亮色下 `#c9a063` 对白底 2.31:1，且 `ring-ring/50` 半透明进一步稀释。不改的理由：
它是品牌点睛色（`docs/brand.md` 口径），改明度属品牌表达决策，需 owner 定；
且修复路径不是换色相，而是把不透明度提到 100% 或加 2px 深色内描边——那是另一个议题，
本批只留记录，不混入。
