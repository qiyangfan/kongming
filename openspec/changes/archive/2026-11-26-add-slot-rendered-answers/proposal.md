# Proposal: add-slot-rendered-answers(答案数字改为槽位渲染,数值白名单退役)

## Why

现状是「模型自由成文 → 数值抽取 + 白名单比对 → 含非白名单数字的句子整句剥离 →
剥空回落统计旁白」。该机制对任意租户、任意数据源不可穷举:

- 问句前提数字(阈值 100)不在白名单,「超过 100 美元的订单共 0 条」被整句删除,
  界面只剩 `共 1 行,count 最大值 0…`(库内 message 01a21209,已离线复现);
- 含数字标签(评级 `PG-13`)被抽成数值,无任何数字的正确回答也被剥空(已复现);
- 日期/期间片段、租户自有编码形态同理,合法数字样片段是开放集合,补不完。

后果是把「不敢说」变成「答非所问」:34 条成功回答中 5 条为统计旁白兜底(库内实测),
且剥离计数未入 trace,不可观测。

前置探针:槽位契约提示词在主模型(qwen-plus)上两个样本(分组标签、月度序列)零违约,
标签与日期均正确以槽位引用。契约可行,无需再扩调研。

## What Changes

- **数字书写权收回系统**:summary/insights(数据态与融合正文的数据部分)的数值与
  含数字标签 MUST 经 `{{槽位}}` 引用,由服务端解析渲染;模型文本去除槽位与引用键
  标记后不得含阿拉伯数字(含全角)。未知槽位/越界/畸形语法即违约,fail-closed,
  不再做自由文本数值抽取与集合比对。
- **槽位命名空间(至少)**:结果行数、stats 统计键、极值标签与值(argmax/argmin,
  统计侧确定性派生)、结果单元格(行列号)、问句前提数字、计算工具返回值、业务
  称谓与物理名。槽位清单由系统按本轮结果形态下发。
- **标量结果确定性作答**:单行单列数值结果由服务端直接生成答案(称谓 + 数值 +
  可识别量词),不调用总结模型。
- **兜底分层**:违约或渲染失败不剥句、不输出 max/min/avg 罗列;多行结果输出
  确定性轮廓(行数 + 极值标签与值)并标注「未生成解读」;违约类型、槽位键与
  兜底层级计入 trace。
- **融合问答**:数据数字走槽位;引用文档内容中的数字仅当为下发原文逐字片段时
  允许,否则整段弃用并退化为纯数据答(来源为空);引用键净化规则不变。
- **退役数值审计三件套**(抽取/白名单/剥句)与统计旁白兜底句;计算工具的入参
  校验保留(结构化入参对可信数值源校验,不是自由文本比对)。
- **提示词同步改写**:SUMMARIZE_SYSTEM、ReAct 最终作答纪律、FUSED_ANSWER_SYSTEM;
  prompt 指纹变化,评测基线重跑。

## Non-goals

- 不改 SQL 生成/防火墙/执行、三态终态、REST/OpenAPI 契约与前端(契约产物应零 diff)。
- 不识别中文数字(一百/两成):现审计本就未覆盖,登记为边界,本变更不加词法扩展。
- 不新增模型重试:违约零额外调用,保持既有时延口径。
- 不覆盖报告生成(report_gen)链路;该链路无此审计,后续单独立项。
- 不提供 per-tenant 槽位或格式化配置;格式只用通用规则(数值保留既有两位小数口径、
  日期取日期部分)。
- 不改引用键净化与来源投影。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `nl2sql-agent`:移除「派生量接地与数值白名单」「确定性数值审计」;新增槽位渲染契约、
  标量确定性作答、违约兜底与可观测;「摘要事实性接地」「计算工具」「趋势与异常类
  洞察收紧」措辞对齐新契约(行为按新口径重述)。
- `knowledge-qa`:「融合问答生成」增加正文数值纪律(数据槽位/文档逐字引用/违约退化)。

## Impact

- agent 侧:summarize、ReAct 收口、fused_answer 三条路径共用同一契约实现;numeric
  模块裁撤审计函数,保留问句数字抽取、计算工具入参校验与派生统计。
- 行为变化:历史 5 条兜底形态(前提阈值、含数字标签、月度序列)产出完整答案句;
  违约场景由统计旁白变为「确定性轮廓 + 未生成解读」。
- 评测:prompt 指纹变化,sakila/olist 评测须重跑并记录新基线,旧基线不可直接比较。
- 无 schema/迁移/契约产物变化;API 与前端零改动。
- 风险:违约率未知但可观测,且违约走确定性兜底不阻断结果面;探针为有限样本,
  apply 阶段以评测 tier 分布复核。

## 引用

- 不涉及信任边界/认证/schema/契约管线(ADR-002/003/004/005 不适用);无新增依赖。
- 遵循 openspec 配置:安全规则类测试先行(契约校验、兜底与 trace 先写失败测试)。
