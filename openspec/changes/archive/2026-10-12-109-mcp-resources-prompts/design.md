# Design

## Context

- mcp-interop 现状:配置管理(headers AES-GCM)+ tools/list 发现动态
  注册(mcp__key__tool,快照存库)+ 执行纵深防御(审计/白名单/断连
  降级)。「MCP 出站不收编工具网关」是 089 已定裁决——原语消费在自有
  注册面内做,不经网关。
- resources/prompts 是 MCP 协议可选能力(server 可以不实现),探测必须
  容忍「不支持」与「失败」两种形态(前者计数 0,后者降级记录)。

## Goals / Non-Goals

**Goals:**

- 三类原语齐备的协议完备性:工具(既有)+ 资源(读取)+ 模板(只读
  预览),复用既有注册面/防御面,新增机制收敛在探测扩展与一个工具。

**Non-Goals:**

- 模板作为运行时提示来源(Bot/Agent 引用 server prompt 组装系统提示)
  ——与 bot/custom-agent 域交叉,等真实需求再立项;本变更模板只读。
- 资源订阅/变更通知(resources/subscribe)——轮询语义不存在,资源
  读取是按需拉取。
- 资源写入/模板创建(MCP 只读原语面,写向原语不在协议消费范围)。
- 二进制资源(mimeType 二进制类拒绝,文本类才读——观察是文本形态)。

## Decisions

1. **读资源聚合为一个工具而非每资源一工具**:资源数可能多,逐资源注册
   会撑爆工具目录与注入集;`read_resource(uri)` + 白名单校验(命中已
   枚举清单)既收敛目录又保留服务端枚举的治理语义。备选(逐资源工具)
   否决。
2. **白名单来自探测快照**:资源 uri 校验以最近一次成功探测的资源清单
   为准(快照存库,同工具注册既有形态)——server 未重新探测前,新增
   资源不可读(与工具发现的「同步后可见」口径一致)。
3. **prompts/get 预览实时拉取而非快照**:模板渲染带 arguments,快照
   无法表达渲染结果;预览是管理面低频动作,实时拉取+注入检测+大小
   上限即可,不落库(隐私与时效)。
4. **原语探测失败与不支持的区分**:端点返回方法不存在/能力未声明 =
   不支持(计数 0,测试判定不受影响);超时/拒连/协议错 = 失败(结构化
   错误,既有分类)。探测容错让「只有工具的简单 server」零感知。
5. **快照列而非新表**:资源/模板清单快照随既有工具快照同列族存储
   (server 配置行扩展 jsonb 列),量级小、生命周期同 server 行,
   不立独立表。

## Risks / Trade-offs

- [资源内容是外部注入面] → 白名单+截断+注入检测三层,与工具观察既有
  防线同构;二进制 mime 直接拒绝(不进观察)。
- [探测扩展拖慢连通性测试] → 三原语探测并行发起,单原语超时短封顶;
  不支持即时短路,量级无虞。
- [read_resource 与工具执行纵深的接缝] → 工具注册走既有形态(命名/
  快照/目录),执行走既有回调纵深——零新机制,回归面小。

## Migration Plan

1. 迁移(server 配置行加原语快照列,纯增);2. 探测扩展 + 清单存库;
3. read_resource 注册与执行适配(测试以进程内 MCP 桩先行);4. web
   详情页清单展示。回退 = revert(列留存无害)。
