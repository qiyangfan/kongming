# 文档多查询分解召回

## Why

文档问答当前是单次召回:一个问句只走一遍混合检索,取父块 top-5 作答。
复合/比较多跳问题需要两份以上文档证据时,单查询的嵌入与词面只对齐一个
证据位置,另一份证据进不了候选池。30 题真实公开文档(K8s)诊断显示:8 道
失配题缺 10 个 gold 父块,其中 7 个不在任一路候选前 8、也不在融合前 10;
父块 top-5 放大只能修回 2 道整题,跨文档全跳仍 0/6。实验室判别实验
(模型拆分问句 → 逐子查询走现有召回 → 父块并集)显示:同文档多跳全跳
0.667→1.000,跨文档 0/6→1/6,单跳在朴素拆分下 1.000→0.833(拆分改写
丢失原问信号)。

结论:缺口在查询规划层,不在召回参数层。分解能力应建在 agent 侧,
且必须保留原问句、只对复合问题生效。

## What Changes

- 意图路由(`INTENT_ROUTE`)的同一次模型调用新增可选 `subqueries` 字段:
  仅 knowledge/fused 且问题包含多个可独立检索的主题、比较对象或并列条件时,
  给出 2-3 条自含子查询;保留专有名词,不得改写为陈述句或答案。
- retrieve 节点:先按原问句检索(行为不变),有子查询时并行补检文档通道,
  按引用键去重合并父块,原问句命中优先,合并上限 8 条。
- doc_answer 与 fused_answer 的文档段注入上限由 5 放宽到 8(仅当合并后
  确有增量;单查询路径仍为 5 条,输出不变)。
- 分解失败、子查询零命中或检索异常时回退原问句单次检索;不新增失败终态。
- schema、指标、历史 SQL 与 SQL 执行链路不读取子查询结果。

### Modified Capabilities

- `nl2sql-agent`:文档通道召回增加「原问句单次 + 子查询并行补检 + 父块
  去重合并」形态,单主题问题保持原行为。

## Impact

- 仅 agent 进程:新增一次意图调用内的字段解析、子查询并行召回与合并;
  不新增模型调用轮次。
- 多跳知识/融合问题的文档上下文最多 5→8 个父块(每块注入仍截 1500 字),
  延迟增加 N 次文档召回(并行);单主题问题零变化。
- 接口、数据库、schema、引用键与既有 SQL 链路不变;prompt 指纹随意图
  路由提示变化。
- 评测:实验室判别已给出覆盖增量;上线前按同一题集复核单跳不回归,
  跨文档组仅报告不设承诺。

## Non-goals

- 不承诺跨文档多跳全跳:子查询仍可能召不回第二份文档的证据,该边界单列。
- 不改召回级参数(`_CHILD_TOP_K`/`_PARENT_TOP_K`)、RRF、精排与分词。
- 不引入 Nacos/DB 动态配置、新中间件或新模型调用轮次。
- 不改 SQL 通道、融合判定、引用净化与答案提示纪律。
- 不做答案级质量承诺;本轮验收以证据覆盖与单跳/链路等价为准。
