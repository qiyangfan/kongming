# Proposal: share-turn-registry(在途轮登记跨实例共享)

## Why

问答轮真取消(add-chat-turn-cancel,已归档)把「取消一轮在途问答」做实了,但
在途轮登记表是进程内单例:取消请求只有落到持有该轮的同一个 api 进程才命中。
多实例部署下(反代轮询、横向扩容),取消有相当概率落到别的实例——该实例本地
查不到这一轮,只能按「已结束且无落库结果」返回 404,前端提示「本轮已结束,
没能取消」,而那一轮实际还在另一个实例上跑完并落库。用户看到的是谎报。

已归档变更把这条列为「已知限制:单节点部署形态下才保证命中」。单进程是当前
compose 部署的偶然形态,不是设计 invariant:反代一开轮询、或 api 扩容到两个
副本,取消就静默退化成谎报,且没有任何测试会红。隔离不能建立在「现在只有
一个进程」上。

## What Changes

- **在途轮登记改跨实例共享**(新端口 + Redis 实现):流式轮启动时在 Redis 登记
  `trace_id → {归属用户, 持有实例地址}`(带 TTL,键存活期即轮次在途期),轮次
  收敛或异常退出时按凭据注销;同名轮(客户端自带 X-Trace-Id 撞号)不会互相
  顶掉对方的登记。
- **取消端点跨实例生效**:本实例登记表未命中时,凭共享登记把取消请求经内部面
  转发给持有该轮的实例,由它执行既有取消编排(通知 Agent 面 + 等本轮收敛),
  结果原样回传。归属校验不变:他人轮次仍 404 同形。
- **新增内部端点** `POST /internal/chat/turn-cancel`(内部令牌,ADR-002 内部
  通道):供同类实例调用,携带轮次标识与归属用户。
- **降级路径**:共享登记不可用(Redis 故障)或转发失败时,按既有落库结果回答
  (有行→COMPLETED,无行→404),不伪造终态;指向本实例却不在途的陈旧键(实例
  重启残留)不自我转发,防自环。
- **前端断开后的中继内存卫生**(同属流式轮生命周期):SSE 中继生成器异常退出
  (前端断开、取消、发送失败)时,就地丢弃消费任务后续入队的帧直到终止标记——
  后台照常落库,但不在内存里为无人接收的帧堆队。

## Impact

- 受影响规格:`query-streaming`(取消端点与归属校验——跨实例生效与降级路径)。
- 新配置:`KM_API_SELF_BASE_URL`(本实例对同类实例可达的自报地址,缺省按主机名
  推导;多实例部署须保证唯一)、`KM_TURN_REGISTRY_TTL_SEC`(登记键 TTL,须大于
  单轮 agent 流上限 + 收敛余量)。
- 新内部端点进 OpenAPI 契约(与既有 `/internal/*` 同 tag),需重生契约产物;
  `.env.example` 同步登记两个新配置(有测试把守)。
- 无 schema 变更;不触碰 `apps/agent` 与 `apps/web`;取消端点对外契约(请求/
  响应/错误码)不变。

## Non-goals

- 不做 Agent 面的跨实例中止:Agent 面中止仍是 best-effort(打错实例即答「未在
  执行」),由控制面硬取消断开连接兜底;转发设计保证取消总能落到持有该轮的
  实例,中止通知与图执行同实例的概率与现状相同。
- 不给 Agent 面帧队列设上限:其唯一消费者(控制面消费任务)断开时图执行会被
  取消,队列不会无限增长;设有界反而在图执行与读取速度不匹配时引入堵死风险
  (见 design)。
- 不引入注册中心/服务网关/分布式事务(宪法 Article I):实例地址由实例自报,
  一个键 + 一次内部面调用,不建注册体系。
- 不改消息第五态、落库语义与前端停止交互。
