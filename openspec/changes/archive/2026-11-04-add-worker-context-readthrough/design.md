# Design: add-worker-context-readthrough

## Context

两处裸截断:分工 worker 派发上下文摘要截断 2000 字(`collab_gen.py:309`),圆桌黑板转写 12 条单行紧凑 + 2000 字(`roundtable_gen.py:120-136`)。worker 本体是 ReAct 图,工具面 = 任务授权 ∩ bot 名单(fail-closed),已有完整的「agent 工具 → api /internal 回调」取数模式。

## Goals / Non-Goals

- Goals: 截断→续读一跳打通;授权零放大;不截断零行为变化。
- Non-Goals(设计层): 不做多跳引用(摘要→对象→对象的链);不做续读结果的缓存;不改两处截断的阈值。

## Decisions

### D1: 入口 = 截断尾部提示文本,不是新数据结构

摘要组装处在发生截断时于尾部追加固定指引(任务标识 + 「task_context 工具可读全文」),纯文本、零 schema。备选「结构化引用对象 + 通用取用协议」是链式召回的形态,本期明确不做(Non-goal),避免为一跳建协议。

### D2: `task_context` 工具进 worker 缺省工具集,授权交集外加

只读自身任务上下文不含数据源访问,读自己任务的上下文不构成提权——故不进「任务授权 ∩ bot 名单」的交集求值,作为 worker 缺省内置工具(与结果回写类内部回调同性质)。跨任务拒绝在 api 端点按任务的 tenant/user 归属校验(worker 调用携带的 task_id 必须等于其正在执行的任务),非归属 404 同形。备选「进交集由授权配置」不取:会把一个无风险的自身只读操作变成逐 bot 配置负担。

### D3: 取数端点 = `/internal/task-context`,复用既有读用例

api task router 增内部端点(X-Internal-Token):入参 task_id,返回 goal 全文 + 已完成步骤的结论与证据引用(复用 `get_task_system`/步骤查询,不新写取数逻辑)。payload 上限钳制(如 8KB)防极端长任务撑爆 worker 窗口——续读是按需补救,不是整份下传的旁路。agent 侧工具实现走既有内部回调模式,超时/错误按工具失败语义进 ReAct 循环(模型可重试或放弃,不炸任务)。

### D4: 圆桌黑板入口同款处理

黑板转写截断时尾部附同一提示;参与者经同一 `task_context` 工具续读——读的是任务级上下文,不是其他参与者原始输出(点对点直连禁令不受影响,spec 场景已覆盖)。

### D5: 对照实验作数据积累,不设门槛

实现后用现有 eval 集跑一组「摘要 vs 摘要+续读」对照,记录 worker 成功率与返工轮次到 eval 报告——只留数据不立验收线(证据不足以立阈值,避免拍脑袋门槛)。

## Risks / Trade-offs

- [worker 滥用续读绕过体积受控] → 工具是按需显式调用,单次 8KB 上限;ReAct 轮次预算天然约束调用次数;截断提示措辞引导「需要时才读」。
- [/internal/task-context 被其他内部调用方滥用] → X-Internal-Token 既有守门 + task 归属校验;端点只读,无副作用面。
- [提示文本干扰未截断场景] → 提示仅在发生截断时附加,未截断路径字节级不变。

## Migration Plan

零迁移。agent 与 api 同版部署(工具提示与端点同时可用;仅 api 先行时提示指向不存在工具——故按同批部署,组合上无灰度需求)。回滚即还原两处摘要组装与工具注册,无数据残留。
