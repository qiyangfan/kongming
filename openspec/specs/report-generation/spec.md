## Purpose

把问数产出从「会话内一问一答」升级为「可保存、可版本化、可导出的分析交付物」:报告 = 元数据 + 章节树,生成过程复用既有问数链路取数(只读 + 六层防御)与沙箱绘图,叙述数据断言与实际执行结果强绑定。报告是通用智能体化的第一个纵向消费者,不引入新的执行通道——信任边界(ADR-002)与既有工具防御面零改动。

## Requirements

### Requirement: 报告生成入口

系统 SHALL 提供两个生成入口,行为同源:(a) 会话内一键生成——以该会话既有的问答产物(SQL/结果/图表/洞察)为上下文,叠加用户补充要求;(b) 直接指令生成——用户以自然语言陈述报告目标与数据范围,系统自主经问数链路取数。两入口的生成请求 SHALL 携带归属主体(user/tenant)与数据源上下文,权限点 `report:generate`;生成 SHALL 为异步过程,发起后立即可查询进度状态(规划中/取数中/撰写中/组装中/终态),终态 ∈ {ready, failed, partial}(partial 见生成预算一节)。

#### Scenario: 会话一键生成

- **GIVEN** 会话已含三轮成功问答(销售额趋势/_topN/异常点洞察)
- **WHEN** 用户点击「生成报告」并补充「面向周会,重点讲异常」
- **THEN** 系统以三轮问答产物为上下文发起异步生成,进度可查,终态为 ready 且报告章节覆盖三轮结论

#### Scenario: 直接指令生成

- **GIVEN** 用户无既有会话,直接指令「出一份近 30 天华东区销售分析报告」
- **WHEN** 发起生成
- **THEN** 系统经问数链路自主取数后产出报告,行为与入口 (a) 的章节契约一致

#### Scenario: 未授权生成被拒

- **GIVEN** 调用方角色集不含 `report:generate`
- **WHEN** 发起报告生成
- **THEN** 接口层拒绝(403 口径)并落 perm_denied 审计,不产生任何报告副作用

### Requirement: 报告结构契约

报告 SHALL 由元数据与章节树构成。元数据 MUST 含:标题、生成时间、数据时点、数据源标识、版本号、状态。章节树 SHALL 支持至少一层嵌套(章/节),每个叶子节点 MUST 含:标题、中文叙述(markdown)、数据绑定集合、图表配置(可为空)。数据绑定 MUST 是可再执行的引用:SQL 文本 + 执行时结果快照(列/行,行数有上限,超出截断并标注);图表配置 MUST 与既有 chart artifact 配置同构,消费端复用既有渲染器。叙述 MUST NOT 内嵌裸执行结果之外编造的数值——数值断言的来源约束见「数据真实原则」。

#### Scenario: 章节数据绑定可再执行

- **GIVEN** 一份 ready 报告的某章绑定查询 Q(快照 200 行)
- **WHEN** 对该章执行「刷新数据」
- **THEN** 系统重新执行 Q(全量防御),以新结果产生新版本,旧版本快照不变

#### Scenario: 图表配置复用既有渲染

- **GIVEN** 章节携带图表配置(类型/轴/系列)
- **WHEN** 前端渲染报告
- **THEN** 图表以与既有 chart artifact 相同的组件与主题渲染,无新渲染路径

### Requirement: 数据真实原则

生成期的一切取数 SHALL 走既有问数执行链路:SQL 防火墙、行级数据范围改写、只读池、六层工具防御,无报告专用旁路。章节叙述中的数值断言 MUST 来自本报告内实际执行成功的查询快照;绑定查询执行失败的章节,叙述 SHALL 如实标注「数据缺失」与失败原因摘要,SHALL NOT 编造数值或以估计值冒充(与 ReAct 账本「有证据才完成」同源)。取数阶段被防御层拒绝的查询 SHALL 视为失败章节处理,SHALL NOT 换写绕过防御的替代 SQL 重试——LLM 可修正 SQL 语义后重试,但修正稿同样过全量防御。

#### Scenario: 查询失败如实标注

- **GIVEN** 生成中某章绑定查询因越权被 data_scope 改写后返回空
- **WHEN** 该章撰写
- **THEN** 叙述标注数据缺失及原因摘要,无数值断言,报告终态仍可为 ready(部分章节缺数)

#### Scenario: 防御拒绝不绕道

- **GIVEN** LLM 产出的取数 SQL 被防火墙拦截
- **WHEN** 生成流程处理
- **THEN** 不存在绕过防火墙的取数路径;LLM 修正后的 SQL 重新过全量防御

### Requirement: 版本化与快照语义

报告 SHALL 版本化:首次生成为版本 1,此后每次「编辑保存」或「刷新数据」产生新版本,版本号单调递增;历史版本 SHALL 只读可查,SHALL NOT 被覆盖或修改。章节数据为**生成/刷新时点快照**——同版本内查看恒返回同一份快照,不随库中数据漂移。报告编辑 SHALL 仅作用于最新版本;并发编辑以后提交者基于最新版本合并校验,冲突时拒绝并提示刷新。

#### Scenario: 编辑产生新版本

- **GIVEN** 报告当前版本 3
- **WHEN** 用户编辑叙述并保存
- **THEN** 产生版本 4,版本 3 完整可查,内容与保存时一致

#### Scenario: 快照不漂移

- **GIVEN** 报告版本 2 的某章快照为 100 行
- **WHEN** 库中数据增长后再次查看版本 2
- **THEN** 该章快照仍为生成时的 100 行,不重执行

#### Scenario: 并发编辑冲突

- **GIVEN** 用户 A 与 B 基于版本 5 同时编辑
- **WHEN** A 保存(产生版本 6)后 B 提交
- **THEN** B 的提交被拒绝并提示基于最新版本刷新,不静默覆盖

### Requirement: 生成预算与部分完成

报告生成 SHALL 受报告级预算约束(步数/LLM token/时长,部署级可配,缺省值实现定)。预算耗尽时生成 SHALL 停止并落库**部分报告**:已完成章节正常,未完成章节如实标注「未完成」,报告终态为 partial,SHALL NOT 谎称完成(与「预算退出诚实」同源)。生成失败(LLM 不可用/链路错误)终态为 failed,已产出章节保留在报告中供诊断,SHALL NOT 静默丢弃。生成全过程的 LLM 调用 SHALL 落既有用量采集,报告维度可归集(协议归因口径与 077 一致);过程事件 SHALL 挂同一 trace 语义,可在既有 trace 时间线查看。

#### Scenario: 预算耗尽部分落库

- **GIVEN** 五章报告生成到第三章时 token 预算耗尽
- **WHEN** 生成停止
- **THEN** 报告终态 partial,前三章完整、后两章标注未完成,报告元数据不声称全部完成

#### Scenario: 用量可归集

- **GIVEN** 一次报告生成消耗 12 次 LLM 调用
- **WHEN** 查询用量看板按报告维度筛选
- **THEN** 该次生成的 token 用量与失败次数可归集到该报告

### Requirement: 导出

系统 SHALL 提供报告 markdown 导出(权限点 `report:export`):导出内容 = 元数据 + 全部章节(叙述 + 数据绑定快照的表格形式 + 图表配置的数据表),查询结果的导出行数与快照截断口径一致;图表在 markdown 中降级为其数据表,SHALL NOT 输出图片或外部链接。导出动作 SHALL 落审计(报告标识/版本/操作者)。

#### Scenario: markdown 导出完整可读

- **GIVEN** 一份 ready 报告(两章,各含图表)
- **WHEN** 导出 markdown
- **THEN** 产出含标题/时点/版本的文档头,章节叙述与数据表完整,图表以数据表呈现

#### Scenario: 导出审计留痕

- **GIVEN** 用户导出版本 3
- **WHEN** 导出完成
- **THEN** 审计记录含报告标识、版本 3、操作者与时间

### Requirement: 报告列表与访问控制

报告 SHALL 有归属(创建者 user + tenant),列表查询仅返回本人本租户报告(行级可见性与既有审计查询口径同构);报告读取权限点 `report:read`,他人报告不可见(404 同形口径)。报告删除 SHALL 为软删仅留痕(状态置 DELETED),已删除报告不出现在列表与详情,导出与再生成被拒。

#### Scenario: 他人报告不可见

- **GIVEN** 用户 B 持有用户 A 的报告标识
- **WHEN** B 请求详情/导出/刷新
- **THEN** 一律 404 同形,不泄露存在性

#### Scenario: 删除后不可再操作

- **GIVEN** 报告已删除
- **WHEN** 以原标识导出或刷新数据
- **THEN** 拒绝,报告不出现在列表
